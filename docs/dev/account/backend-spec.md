## 7. DB 설계

### 7.1 products (상품, 3행 고정)

| 컬럼 | 타입 | 제약 | 설명 |
|---|---|---|---|
| id | BIGINT | PK, GENERATED BY DEFAULT AS IDENTITY | 1 저축예금, 2 정기예금, 3 정기적금 (시드로 id를 고정하므로 BY DEFAULT) |
| type | TEXT | NOT NULL | checking / deposit / savings |
| name | TEXT | NOT NULL | 상품명 |
| description | TEXT | | 상품 설명·유의사항 (RAG 문서와 동일 내용) |
| rate | NUMERIC(5,2) | NOT NULL | 연금리 (%) |
| early_close_rate | NUMERIC(5,2) | NULL 허용 | 중도해지 연금리 (%) |
| min_amount | BIGINT | NULL 허용 | 최소 금액 (예금: 예치액, 적금: 월 납입액) |
| max_amount | BIGINT | NULL 허용 | 최대 금액 |
| min_months | INTEGER | NULL 허용 | 최소 기간 |
| max_months | INTEGER | NULL 허용 | 최대 기간 (적금은 12 고정) |
| max_per_user | INTEGER | NULL 허용 | 1인 보유 한도 (저축예금 5, 적금 1, 예금 NULL) |
| requires_checking | BOOLEAN | NOT NULL, DEFAULT false | 저축예금 보유 필요 여부 (예적금 true) |

### 7.2 accounts (계좌)

| 컬럼 | 타입 | 제약 | 설명 |
|---|---|---|---|
| id | BIGINT | PK, GENERATED BY DEFAULT AS IDENTITY | 시드로 id 1~6을 고정하므로 BY DEFAULT. 시드 뒤 시퀀스를 맞춘다 |
| user_id | BIGINT | FK users.id, NOT NULL | 소유자 (dev/auth/backend-spec.md 8.2) |
| product_id | BIGINT | FK products.id, NOT NULL | |
| account_no | TEXT | UNIQUE, NOT NULL | 계좌번호 (예: 1002-123-456789, 우리은행 형식 참고) |
| alias | TEXT | | 계좌 별명 |
| balance | BIGINT | NOT NULL, DEFAULT 0 | 잔액 (원). 예적금은 원금 누계 |
| rate | NUMERIC(5,2) | NOT NULL | 개설 시점에 확정된 연금리 |
| term_months | INTEGER | NULL 허용 | 가입 기간 (예적금) |
| monthly_amount | BIGINT | NULL 허용 | 월 납입액 (적금) |
| payment_day | INTEGER | NULL 허용 | 납입일 (적금) |
| paid_count | INTEGER | DEFAULT 0 | 납입 회차 (적금) |
| auto_pay | BOOLEAN | NOT NULL, DEFAULT true | 자동이체 여부 (적금만 의미. 기본 켜짐) |
| linked_account_id | BIGINT | FK accounts.id, NULL 허용 | 납입 출금·만기 입금에 쓰는 저축예금 (예적금) |
| opened_at | DATE | NOT NULL | 개설일 |
| maturity_date | DATE | NULL 허용 | 만기일 (예적금) |
| status | TEXT | NOT NULL, DEFAULT 'active' | active / matured / closed_early / closed |
| closed_at | TIMESTAMPTZ | NULL 허용 | 해지 일시 |
| is_primary | BOOLEAN | NOT NULL, DEFAULT false | 대표계좌 여부 (저축예금만) |

### 7.3 transactions (거래)

| 컬럼 | 타입 | 제약 | 설명 |
|---|---|---|---|
| id | BIGINT | PK, GENERATED ALWAYS AS IDENTITY | |
| account_id | BIGINT | FK accounts.id, NOT NULL | 거래가 발생한 계좌 |
| type | TEXT | NOT NULL | open / deposit / transfer_in / transfer_out / interest / close / loan_disbursement / loan_repayment (`card_payment`는 이름만 예약) |
| amount | BIGINT | NOT NULL | 금액 (양수, open은 0) |
| balance_after | BIGINT | NOT NULL | 거래 후 잔액 |
| counterparty_account_id | BIGINT | FK accounts.id, NULL 허용 | 상대 계좌 (이체·납입·해지 입금 시) |
| counterparty_name | TEXT | | 상대 표시명 (예금주 이름, "ATM 입금", "정기적금 3회차 납입" 등) |
| memo | TEXT | | |
| ref_type | TEXT | NULL 허용 | 이 거래를 만든 업무. 현재 `loan`만 쓴다 (대출 지급·상환) |
| ref_id | TEXT | NULL 허용 | 업무 쪽 키. 대출은 계약번호(예: LA-2026-123456). 인덱스 (ref_type, ref_id) |
| created_at | TIMESTAMPTZ | NOT NULL, DEFAULT now() | |

### 7.4 favorite_accounts (자주 쓰는 계좌)

| 컬럼 | 타입 | 제약 | 설명 |
|---|---|---|---|
| id | BIGINT | PK, GENERATED ALWAYS AS IDENTITY | |
| user_id | BIGINT | FK users.id, NOT NULL | |
| account_no | TEXT | NOT NULL | 상대 계좌번호 |
| display_name | TEXT | | 표시 이름 |
| created_at | TIMESTAMPTZ | DEFAULT now() | |

- 이체·납입·해지 입금은 모두 출금 계좌의 transfer_out과 입금 계좌의 transfer_in 2건을 같은 트랜잭션에서 기록한다. 해지 이자는 입금 계좌에 interest 1건을 추가로 기록한다.
- `open`은 저축예금 개설 때만 기록한다(0원). 예적금 개설은 출금·입금 2건(transfer_out/transfer_in)만 기록한다. `close`는 계좌가 해지될 때 해지된 계좌에 0원으로 1건 기록한다.
- 최근 이체 계좌는 별도 테이블 없이 transactions의 transfer_out(사용자의 저축예금에서 나가고 상대가 저축예금인 것)을 최신순으로 조회해 만든다. 1일 이체 한도(1천만원)도 같은 기준으로 당일(KST)의 합계를 구해 검사한다. 적금 납입, 예적금 개설·해지는 상대가 저축예금이 아니거나 출금 계좌가 예적금이라 합계에 들어가지 않는다.
- 이번 범위에서는 카드 결제를 기록하지 않는다. transactions.type의 `card_payment`는 이름만 예약해 둔다 (결정기록.md 10장).
- 대출 지급·상환(2026-11-06 추가): `loan_disbursement`(입금, 대출금 지급)와 `loan_repayment`(출금, 중도상환·청약철회 반환)를 저축예금에 기록하고 `ref_type='loan'`, `ref_id=계약번호`를 남긴다. 거래 내역의 입금/출금 필터는 이 두 유형을 각각 입금·출금으로 본다. 가계부 수입에는 넣지 않는다(대출금은 수입이 아니다). 대출 파트가 부르는 함수는 `loan_disburse(db, user_id, account_id, amount, contract_no)`, `loan_repay(db, user_id, account_id, amount, contract_no, memo)`, `checking_for(db, user_id, account_id)`이고, 내 저축예금(active)만 받으며(아니면 404/409) 잔액이 모자라면 `422 INSUFFICIENT_BALANCE`다. 커밋하지 않고 호출한 대출 처리와 한 트랜잭션으로 묶인다(공통.md 8장).
- PostgreSQL 기준 타입이다(공통.md 6장). 금액은 BIGINT(원 단위 정수), 금리는 NUMERIC(5,2), 시각은 TIMESTAMPTZ, 불리언은 BOOLEAN, 식별자는 BIGINT IDENTITY. 스키마는 Alembic 마이그레이션으로 관리한다.
- 이체·납입·해지의 "한 트랜잭션" 처리는 SQLAlchemy 세션 하나에서 출금·입금·거래 기록을 모두 수행한 뒤 commit하고, 예외 시 rollback한다. 잔액 갱신 시 `SELECT ... FOR UPDATE`로 두 계좌 행을 잠가 동시 이체를 막는다.
- 시드 데이터: products 3행. 사용자 id 1~4는 공통.md 7.1, 계좌는 삽입 순서대로 id를 고정해 부여하고 계좌번호는 공통.md 7.2의 값을 쓴다. user1의 계좌에 거래 내역 20건을 둔다. user3은 계좌 없음.

| id | 소유 | 상품 | 계좌번호 |
|:---:|---|---|---|
| 1 | user1 | 저축예금 (대표, 1,500,000원) | 1002-123-451234 |
| 2 | user1 | 저축예금 (생활비, 500,000원) | 1002-123-455678 |
| 3 | user1 | 정기예금 (3,000,000원, 12개월, 개설 6개월 전) | 1002-223-460003 |
| 4 | user1 | 정기적금 (월 200,000원, 3회차 납입, 잔액 600,000원, 개설 3개월 전) | 1002-323-460004 |
| 5 | user2 | 저축예금 (300,000원) | 1002-123-459000 |
