## 1. 결정 사항

- 백엔드 FastAPI, 프론트 React, DB PostgreSQL + pgvector, LLM Gemini API로 간다.
- 서버 렌더링이 아니라 "JSON API 서버 + 별도 프론트" 구조다. 기획서의 DB·세션·접근 제어 설계는 그대로 쓰고, 화면 보호와 화면 이동 부분만 API 방식으로 바꾼다(5장).

## 4. 자연어 입력 구조

- `google-genai`의 함수 호출은 파이썬 함수를 `tools`에 그대로 넘기면 모델이 호출할 함수와 인자를 정해 주고, 자동 함수 호출 옵션을 켜면 SDK가 실행까지 한다.
- 구조: 홈 입력창 → 라우터 → 도메인 에이전트(auth / acc / card / ledger / loan). 아래 도구는 해당 도메인 에이전트에 나뉘어 등록된다 (공통.md 9장).
- 등록할 도구: 계좌 함수(잔액 조회, 계좌 목록, 거래 내역, 입금, 이체, 적금 납입, 계좌 개설 안내, 이자 조회, 해지 예상 이자), 카드 함수(카드 목록·상세, 이용내역, 청구 예정, 한도, 정지·해제·분실 신고, 해지 가능 확인. card/08-natural-language.md), 인증 함수(로그아웃, 내 정보, 휴대폰 변경, 기기 등록 해제), RAG 함수(search_docs).
- user 주입, 돈이 움직이는 동작의 확인 질문(2단계 도구), 본인 재확인, 미인증 상태의 허용 의도 같은 **에이전트 규칙은 [공통.md 9.2](공통.md#92-모든-에이전트가-지키는-규칙)** 를 따른다. 함수 시그니처에서 user 인자를 빼고 클로저나 의존성으로 넣는다.
- RAG는 `search_docs(query)` 도구 하나로 등록한다. 질문을 임베딩한 뒤 pgvector에서 코사인 거리 상위 5개 청크를 가져와 모델에 돌려준다.
- 대화 맥락은 세션에 최근 5턴, 전체는 chat_messages에 저장한다(dev/auth/backend-spec.md 8.3). google-genai의 chat 객체는 요청마다 새로 만들고 history를 세션에서 복원한다.
- 응답을 실시간으로 보여 주려면 /api/chat을 SSE로 스트리밍한다. 필수는 아니다.

## 5. 기획서에서 바뀌는 것

### 5.1 보호 장치

`current_user` 의존성과 라우터 적용 예시는 [회원-인증.md 6.1](../auth/회원-인증.md)이 원본이다 (규칙은 [공통.md 3장](공통.md#3-인증접근-제어-api-규약), 오류 코드는 [오류코드.md](오류코드.md)). 서버 렌더링 때와 달라지는 점만 적는다.

- 서버가 리다이렉트하던 동작(미인증 → 로그인, 로그인 상태에서 /login → 홈, 미설정 → S-07)은 프론트 라우터가 401/403 코드를 보고 처리한다.
- "로그인 후 원래 화면 복귀(next)"는 React Router의 location state로 처리한다. next 검증(내부 경로만)은 프론트에서 한다.
- 2차 인증(S-08)은 프론트가 화면을 띄우고 `/api/auth/pin/verify`를 호출한 뒤 통과하면 해당 API를 호출한다 ([공통.md 4장](공통.md#4-본인-재확인-2차-인증-간편비밀번호)).

### 5.2 DB 표기 (dev/auth/backend-spec.md 8장, dev/account/backend-spec.md 7장)

- SQLite 타입 표기를 PostgreSQL로 바꾼다. INTEGER PK AUTOINCREMENT → `BIGINT GENERATED ALWAYS AS IDENTITY`, DATETIME → `TIMESTAMPTZ`, DATE 그대로, INTEGER(0/1) → `BOOLEAN`, 금액 INTEGER → `BIGINT`.
- 설계(테이블·컬럼·관계·규칙)는 그대로다.

### 5.3 RAG 테이블 추가

```sql
CREATE EXTENSION IF NOT EXISTS vector;

-- 기존 rag_documents(source_url, title, version, chunk_text, effective_date)에 임베딩 컬럼을 더한다.
-- 별도 doc_chunks 테이블은 만들지 않는다.
ALTER TABLE rag_documents ADD COLUMN IF NOT EXISTS embedding vector(768);
CREATE INDEX ON rag_documents USING hnsw (embedding vector_cosine_ops);
```

- 임베딩 컬럼을 새 테이블이 아니라 구현된 `rag_documents`에 더하는 것으로 정했다(2026-11-05).
- 검색 대상 문서: 상품 설명 3종(계좌 파트 작성), 계좌 이용 안내, 카드 상품 설명·카드 이용 안내(카드 파트 작성, card/08-natural-language.md 5절), 회원·인증 규칙(비밀번호 규칙, 잠금 정책), 약관.
- 문서를 바꾸면 해당 source_url의 청크를 지우고 다시 임베딩한다. 임베딩 스크립트(ingest.py)를 백엔드에 둔다.

### 5.4 화면

- 7장 화면 ID와 URL은 그대로 React 라우트가 된다. 하단 탭 바 표시 규칙(S-07 첫 설정·S-08에서는 숨김)은 레이아웃 컴포넌트에서 처리한다.

## 7. 개발 환경 세팅 순서

1. DB 준비: 로컬 PostgreSQL 17에 프로젝트 DB를 만들고 pgvector 확장을 켠다 (9.2)
2. .env 작성: `backend/.env.example`을 복사해 DATABASE_URL, SESSION_SECRET, GEMINI_API_KEY를 채운다. GEMINI_API_KEY는 Google AI Studio에서 발급
3. 백엔드: `python -m venv .venv` → `pip install -r requirements.txt` → `alembic upgrade head` → `uvicorn app.main:app --reload` (시드는 서버가 처음 켜질 때 들어간다)
4. 프론트: `npm install` → `npm run dev` (Vite proxy로 /api 연결)
5. 브라우저에서 http://localhost:5173 접속. 백엔드 API 문서는 http://localhost:8000/docs

## 9. 팀원 공유: 각자 준비할 것

### 9.1 별도 서버는 필요 없다

- 개발과 발표 시연까지 전부 각자 노트북에서 돌아간다. 노트북 안에서 PostgreSQL(5432), FastAPI(8000), Vite 개발 서버(5173) 세 개가 돌고, 브라우저로 localhost:5173을 열면 된다.
- 외부에 의존하는 것은 Gemini API 호출뿐이다. DB·백엔드·프론트는 인터넷 없이도 동작한다.
- 배포(링크 제출)는 과제 제출물에 없으므로 필수가 아니다. 원하면 프론트 Vercel, 백엔드 Render/Railway, DB Supabase 무료 플랜으로 올릴 수 있지만, 쿠키 세션이라 도메인이 갈리면 쿠키 설정(SameSite=None, Secure)을 바꿔야 해서 발표 직전에는 하지 않는다.

### 9.2 각자 노트북에 필요한 것

| 항목 | 용도 | 확인·설치 방법 |
|---|---|---|
| Python 3.12 이상 | FastAPI 백엔드 | `python --version` |
| Node.js 20 이상 + npm | React(Vite) 프론트 | `node --version`. 없으면 nodejs.org LTS 설치 |
| PostgreSQL 17 + pgvector | DB, RAG 벡터 저장 | 아래 확인 명령 참고. 미니 프로젝트 때 설치했다면 이미 있을 가능성이 큼 |
| Google AI Studio API 키 | Gemini 호출 | 구글 계정으로 무료 발급. 1인 1키, .env에만 보관하고 저장소에 올리지 않는다 |
| Git | 저장소 공유 | GitHub 저장소 aim-mid-project-team1에 협업자로 초대받기 |

pgvector 설치 여부 확인:

```bash
psql -U postgres -c "SELECT name, default_version FROM pg_available_extensions WHERE name='vector';"
```

행이 나오면 설치된 것이다. 이어서 프로젝트 DB를 만들고 확장을 켠다.

```bash
psql -U postgres -c "CREATE DATABASE aimbank;"
```

```bash
psql -U postgres -d aimbank -c "CREATE EXTENSION IF NOT EXISTS vector;"
```

.env의 접속 주소 형식:

```
DATABASE_URL=postgresql+psycopg://postgres:<비밀번호>@localhost:5432/aimbank
SESSION_SECRET=<아무 긴 무작위 문자열>
APP_ENV=dev   # 시연 API 노출 (운영에서는 비운다)
GEMINI_API_KEY=<AI Studio에서 발급한 키>
```

4명이 각자 노트북의 Postgres에 같은 이름(aimbank)의 DB를 만들고 같은 Alembic 마이그레이션을 돌리면 스키마가 맞춰진다. 서로의 DB에 접속할 일은 없다.

**마이그레이션 사용법** (`cd backend`)

| 하고 싶은 일 | 명령 |
|---|---|
| 코드를 받았다. 테이블을 최신으로 | `alembic upgrade head` (데이터 유지) |
| 지금 DB 가 몇 번인지 | `alembic current` |
| 모델을 고쳤다. 마이그레이션 만들기 | `alembic revision --autogenerate -m "설명"` → 파일을 열어 확인·수정 → `alembic upgrade head` |
| 모델과 마이그레이션이 같은지 | `alembic check` |
| 마이그레이션 도입 전 DB(대출 통합 이후 구조)를 이어 쓰기 | `alembic stamp head` (표시만, 데이터·구조는 그대로) |
| 완전히 새로 | `python reset_db.py --yes` (모든 데이터 삭제) |

- 대출 테이블은 ORM 모델이 아니라 SQL(`app/loan/schema.sql`)로 정의한다. 바꿀 때는 SQL 마이그레이션을 직접 쓰고 `schema.sql`도 같이 고친다. `alembic/sql/0002_loan_schema.sql`은 0002 시점의 복사본이라 고치지 않는다.
- 자동 생성(`--autogenerate`)은 모델에 없는 테이블(대출)을 지우려 하지 않는다(`env.py`의 `include_object`). 생성된 파일은 항상 열어서 확인한다(열 이름 변경은 삭제+추가로 만들어지고, 데이터 이전은 직접 써야 한다).
- 가계부 자유 질문용 읽기 전용 DB 역할(`ledger_query.setup`)은 마이그레이션이 아니라 서버가 시작할 때 만든다(역할은 DB 안이 아니라 서버 전체 설정이고, 권한이 없으면 그 기능만 꺼진다).

### 9.3 pgvector가 없는 경우의 대안

| 순위 | 방법 | 비고 |
|---|---|---|
| 1 | Supabase 무료 플랜 | 클라우드 PostgreSQL, pgvector 기본 포함. 가입 후 접속 주소만 DATABASE_URL에 넣으면 됨. 1인 1프로젝트. 인터넷 필요 |
| 2 | 로컬 Postgres에 pgvector 수동 빌드 | pgvector 깃허브의 Windows 안내대로 Visual Studio Build Tools로 빌드. 번거로워 마지막 선택 |

어느 방법이든 코드는 DATABASE_URL 한 줄만 다르다. 팀 안에서 섞여 써도 된다.

### 9.4 발표 준비

- 발표장 와이파이가 불안하면 Gemini 호출이 막혀 자연어 시연이 멈춘다. 휴대폰 핫스팟을 준비하고, 자연어 입력 시연은 영상으로도 찍어 둔다.
- 발표 직전에는 Gemini 무료 등급의 요청 제한을 피하도록 유료 키로 바꾸거나, 시연에 쓸 문장을 미리 한 번씩 돌려 본다.
- 비용은 전부 무료 범위다. Gemini 무료 등급으로 개발 가능, Supabase 무료 플랜은 프로젝트 2개까지. Gemini 유료 키를 써도 시연·테스트 규모에서는 몇백 원이다.
