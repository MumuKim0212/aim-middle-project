## 1. 목표

> 과제 조건: "계좌, 카드 등 은행의 기본적인 기능들을 클론코딩한다. 계좌 생성의 경우 상품별 금리와 가입 조건 등 실제 은행의 기능 및 UI를 참고하여 진행한다."

- 이 파트가 책임지는 것:
  - 계좌 개설: 상품 3종의 금리·가입 조건을 보여 주고, 조건을 검증한 뒤 계좌를 만든다
  - 계좌 조회: 내 계좌 목록, 계좌 상세, 거래 내역, 예적금 이자 조회
  - 입금: 시연용 현금 입금(ATM 입금 시뮬레이션), 적금 납입(기본은 매월 자동이체, 수동 납입도 가능)
  - 이체: 내 계좌 간 이체, 타인 계좌 이체, 최근·자주 쓰는 계좌
  - 해지: 저축예금 해지, 예적금 만기 해지와 중도 해지(이자 계산 포함)
- 다른 파트에 제공하는 것:
  - products, accounts, transactions, favorite_accounts 테이블 (DB 담당)
  - 계좌 조회·입금·이체·개설·해지·이자 계산 함수 (자연어 담당이 의도별로 호출)
  - 상품 설명·금리·가입 조건 문서 3종 (RAG 담당의 검색 대상)
  - 이체 직전 2차 인증 호출 지점. 필수이며 이체와 예적금 해지에 적용한다 (공통.md 4장)
  - 카드 결제 계좌 후보 조회(`GET /api/accounts?purpose=card_payment`)와 계좌 응답 필드(`accountMasked`, `bankName`, `productType`, `status`) (카드 담당, 공통.md 8장)
  - 카드 결제 시 잔액 차감 함수: 카드는 이번 범위에서 결제를 실행하지 않아 쓰지 않는다 (공통.md 10장). 거래 유형 `card_payment` 이름만 예약
- 완료 기준:
  - 가입 직후 저축예금을 개설하고, 입금·이체·거래 내역 조회가 끊김 없이 동작한다.
  - 정기예금·정기적금을 가입 조건에 따라 개설하거나 거부하며, 거부 사유가 화면에 표시된다.
  - 중도 해지 시 해지 예상 이자가 계산되어 표시되고, 해지 후 원리금이 저축예금으로 입금된다.
  - 이체는 한 트랜잭션으로 처리되어 중간 실패 시 잔액이 변하지 않는다.
  - 로그인한 사용자가 타인의 계좌를 어떤 경로로도 조회·이체할 수 없다.

## 2. 상품 구성 (우리WON뱅킹 참고)

| 항목 | 우리 저축예금 | 우리 정기예금 | 우리 정기적금 |
|---|---|---|---|
| 참고 상품 | 우리 WON통장 | WON플러스 예금 | 우리 WON 적금 |
| 종류 | 입출금 자유 | 목돈 예치, 만기 일시 지급 | 매월 납입, 만기 일시 지급 |
| 금리 (시드 기준값) | 연 0.1% (표시만) | 연 2.9% | 연 3.0% |
| 중도해지 금리 | 해당 없음 | 연 1.0% | 연 1.0% |
| 가입 금액 | 제한 없음 | 1만원 이상 1억원 이하, 1회 예치 | 월 1만원 이상 50만원 이하 |
| 가입 기간 | 없음 | 1~36개월 (1개월 단위) | 12개월 고정 |
| 가입 조건 | 로그인한 사용자 누구나 | 저축예금 보유 | 저축예금 보유, 1인 1계좌 |
| 보유 한도 | 1인 최대 5개 | 제한 없음 | 1인 1계좌 |
| 입출금 | 입금·출금·이체 자유 | 개설 시 1회 입금만. 출금은 해지로만 | 매월 납입만(기본 자동이체). 출금은 해지로만 |
| 만기 처리 | 없음 | 원금+이자를 지정 저축예금으로 입금 | 원금+이자를 지정 저축예금으로 입금 |
| 수수료 | 없음 | 없음 | 없음 |

- 공통 규칙: 시연용 입금 1회 1천만원 이하, 이체 1회 5백만원·1일 1천만원, 타행 이체는 은행 선택 UI만 두고 구현하지 않는다(타행을 고르면 "타행 이체는 준비 중입니다" 안내만 보이고 요청을 보내지 않는다).
- 금리는 시기별로 달라 시드 데이터에 고정값으로 넣는다. 실제 수치는 우리WON뱅킹 상품 페이지에서 확인 후 조정한다.
- 실제 은행의 우대 금리, 자유적립식, 분할 해지, 만기 자동 재예치는 구현하지 않고 상품 설명에만 적는다.

## 3. 필수 기능 목록

| ID | 기능 | 설명 | 비고 |
|---|---|---|---|
| ACC-01 | 상품 안내 | 상품 3종의 금리·기간·금액·가입 조건을 한 화면에서 비교. 각 상품의 상세 설명 펼치기 | 로그인 없이도 조회 가능 (회원,인증.md R1). RAG 문서와 내용 일치 |
| ACC-02 | 계좌 개설 | 상품 선택 → 가입 조건 확인 → 상품별 설정 입력(적금은 자동이체 여부, 기본 켜짐) → 출금 계좌 선택(예적금) → 약관 동의 → 완료. 조건 미충족 시 사유와 함께 거부 | 흐름은 5장 |
| ACC-03 | 가입 조건 검증 | 저축예금 보유 여부, 1인 1계좌, 보유 한도, 금액·기간 범위, 출금 계좌 잔액을 서버에서 검증 | |
| ACC-04 | 계좌 목록 조회 | 내 계좌를 저축예금·정기예금·정기적금으로 구분해 카드형으로 표시. 총 잔액 합계, 대표계좌 표시. 계좌가 없으면 "첫 계좌 만들기" 안내 | 홈 화면의 계좌 요약 영역도 이 기능으로 |
| ACC-05 | 계좌 상세 조회 | 계좌번호, 상품명, 별명, 잔액, 개설일, 금리. 예적금은 만기일·만기 예상 이자·현재까지 쌓인 이자, 적금은 월 납입액·납입 회차 | |
| ACC-06 | 거래 내역 조회 | 기간(1주·1개월·3개월·직접 입력), 입금/출금/전체 필터, 거래 후 잔액 표시. 최신순 정렬 | 페이지당 20건 |
| ACC-07 | 입금 | 시연용 현금 입금(저축예금만). 금액 입력 → 확인 → 잔액 증가, 거래 기록(deposit) | 화면에 "ATM 입금(시연용)" 표시 |
| ACC-08 | 적금 납입 | **기본은 자동이체**: 납입일(1~28일)마다 서버가 지정 저축예금에서 월 납입액을 적금 계좌로 이체한다(5.3). 자동이체를 끈 계좌, 잔액 부족으로 미납인 회차는 상세의 "납입하기"로 수동 납입한다. 이번 달 이미 납입했으면(자동 포함) 거부 | 자동이체 켜기·끄기는 계좌 상세에서. 시연용 "자동이체 실행" 버튼은 개발 모드에서만 |
| ACC-09 | 내 계좌 간 이체 | 저축예금 → 저축예금. 출금·입금 계좌 선택, 금액 입력, 확인, 완료. 잔액 부족 시 거부 | 예적금은 이체 대상에서 제외 |
| ACC-10 | 타인 계좌 이체 | 받는 계좌번호(저축예금만) 입력 → 예금주 이름 확인 → 금액·메모 → 확인 → 완료. 앱 내 사용자 간 이체만 구현 | 타행 이체는 은행 선택 UI만 두고 구현하지 않음 (타행 선택 시 "준비 중" 안내) |
| ACC-11 | 최근·자주 쓰는 계좌 | 최근 이체한 계좌 5건 자동 표시. 자주 쓰는 계좌 등록·삭제 | |
| ACC-12 | 이자 조회 | 예적금의 현재까지 쌓인 이자(경과일 기준)와 만기 예상 이자, 지금 해지 시 받을 이자. 세전 | 계산 규칙은 6장 |
| ACC-13 | 만기 처리 | 만기일이 지난 예적금은 상세(A-04)에서 "만기가 되었습니다. 해지하여 원리금을 받으세요" 안내와 "해지하기" 버튼을 보여 준다. 사용자가 해지하면 5.5 흐름대로 약정 금리 만기 이자를 포함한 원리금이 지정 저축예금으로 입금되고 상태가 "만기해지"(matured)가 된다. 조회(GET)만으로 입금하거나 상태를 바꾸지 않는다 | 시연용 "만기 도래 시뮬레이션" 버튼 허용(개발 모드). 해지하기 전 S-08 필요 (공통.md 4장) |
| ACC-14 | 중도 해지 | 예적금 해지 예상 이자(중도해지 금리) 미리 보기 → 확인 → "해지하기" 전 S-08 간편비밀번호 확인(공통.md 4장) → 원리금을 지정 저축예금으로 입금 → 상태 "중도해지" | 브레인스토밍 "정기예금 미리 깰 경우 이자" 반영 |
| ACC-15 | 저축예금 해지 | 잔액이 있으면 받을 저축예금을 골라 전액 이체 후 해지. 잔액 0원이면 바로 해지. 예적금의 지정 입금 계좌로 쓰이는 중이거나 해지 안 된 카드의 결제 계좌이면 거부(카드 파트의 `count_active_cards(account_id)` 사용, 공통.md 8장). 카드 사유 메시지는 "연결된 카드가 있어 해지할 수 없습니다" | |
| ACC-16 | 본인 계좌 접근 제어 | 모든 계좌·거래 조회와 입금·이체·개설·해지는 세션의 user_id로 필터링. 타인 계좌 URL은 404 | 회원,인증.md R3·R4 적용 |

구현 순서: ACC-01 → 02(저축예금) → 03 → 04 → 05 → 07 → 09 → 06 → 10 → 11 → 02(예적금) → 08 → 12 → 14 → 13 → 15 → 16(전 단계에서 병행).
저축예금 개설·입금·이체를 먼저 완성한 뒤 예적금을 얹는다. 예적금은 저축예금이 있어야 개설·해지가 가능하기 때문이다.

| A-11 | 이체 완료 | /transfer/done | O | 결과 요약, "확인"(계좌 목록으로), "한 번 더 이체" |

- 하단 탭 "계좌"는 A-01로 연결한다. 모바일 폭 420px 고정 레이아웃은 회원,인증.md와 동일.
- 위 URL은 React 라우트 경로다. 백엔드 API는 /api 아래에 둔다(예: GET /api/accounts, GET /api/accounts?purpose=card_payment, GET /api/accounts/{id}/transactions, POST /api/transfers, POST /api/accounts/{id}/deposit, POST /api/accounts/{id}/pay, POST /api/accounts/{id}/auto-pay, POST /api/accounts/{id}/close, GET /api/products). 모든 API는 `Depends(current_user)`로 보호한다(회원,인증.md 6.1).
- 이체 확인(A-10)의 2차 인증은 필수다(공통.md 4장). 프론트가 S-08을 띄워 /api/auth/pin/verify를 통과한 뒤 POST /api/transfers를 호출하고, 서버는 `pin_verified(request)`(5분)로 다시 검사해 안 되어 있으면 `403 PIN_VERIFICATION_REQUIRED`로 응답한다.
- `GET /api/accounts?purpose=card_payment`는 본인 계좌 중 저축예금이고 active인 것만 돌려준다 (카드 파트의 결제 계좌 후보, 공통.md 8장).
- 다른 파트가 쓰는 계좌 응답은 `accountId`, `bankName`(상수 "AIM Bank"), `accountMasked`(끝 4자리), `balance`, `productType`(`checking`/`deposit`/`savings`), `status`를 담는다. 전체 계좌번호는 본인의 계좌 상세 화면에서만 내려준다 (공통.md 6장).
- 개발 모드(환경변수 `APP_ENV=dev`)에서만 시연용 API와 버튼을 연다: `POST /api/dev/accounts/{id}/maturity`(만기일을 어제로 바꿈), `POST /api/dev/auto-pay/run`(자동이체 배치를 지금 실행). 운영 모드에서는 404다.
- 오류 코드는 [오류코드.md](../common/오류코드.md) 4절이다.
- 우리WON뱅킹 참고 요소: 계좌 카드형 목록, 금액 입력 시 한글 금액 표시(예: 10,000원 → 일만원), 단계마다 상단 진행 표시, 계좌번호 복사 버튼, 예적금 카드의 만기 D-day 표시.

## 5. 주요 흐름

### 5.1 계좌 개설

1. 상품 안내(A-02)에서 상품 선택 → "가입하기" → A-03
2. 가입 조건 확인(서버 검증, 미충족 시 사유 표시 후 종료)
   - 저축예금: 보유 한도 5개
   - 정기예금: 저축예금 보유
   - 정기적금: 저축예금 보유, 1인 1계좌
3. 상품별 설정 입력
   - 저축예금: 별명(선택), 대표계좌 여부(첫 계좌는 자동 대표)
   - 정기예금: 예치 금액(1만원~1억원), 기간(1~36개월), 만기 시 입금받을 저축예금
   - 정기적금: 월 납입액(1만원~50만원), 납입일(1~28일), 납입·만기 입금에 쓸 저축예금, 자동이체 여부(기본 켜짐). 기간은 12개월 고정
4. 출금 계좌 확인(예적금): 선택한 저축예금 잔액이 예치 금액(예금) 또는 첫 회 납입액(적금) 이상인지 확인
5. 약관 동의(적금은 "매월 납입일에 지정 저축예금에서 자동 출금" 동의 포함, 자동이체를 끈 경우 제외) → "개설하기"
6. 완료 처리
   - 저축예금: accounts 생성(잔액 0), 거래 기록(open, 0원)
   - 정기예금: 저축예금에서 예치 금액 출금 → 예금 계좌 생성(잔액 = 예치 금액), 만기일 = 개설일 + 기간, 거래 2건 기록(저축예금 transfer_out, 예금 계좌 transfer_in)
   - 정기적금: 저축예금에서 첫 회 납입액 출금 → 적금 계좌 생성(잔액 = 납입액, 회차 1), 만기일 = 개설일 + 12개월, 거래 2건 기록(저축예금 transfer_out, 적금 계좌 transfer_in)
7. 계좌 상세(A-04)로 이동

### 5.2 입금 (시연용, 저축예금만)

1. 계좌 상세(A-04)의 "입금" → A-06
2. 금액 입력(1원 이상, 1회 1천만원 이하)
3. 확인 → 잔액 증가, transactions에 deposit 기록, 상대 표시명 "ATM 입금"
4. 계좌 상세로 복귀

### 5.3 적금 납입 (기본: 자동이체)

**회차와 납입일**: 1회차는 개설할 때 바로 납입한다(5.1). 2~12회차의 납입일은 개설월 + (회차 − 1)개월의 납입일(payment_day)이다.

**자동이체** (accounts.auto_pay가 켜진 적금, 기본 켜짐)
1. 서버가 매일 00:10(KST)에 자동이체 배치를 돌린다. 서버를 따로 띄우지 않고 앱 시작 때 만드는 백그라운드 작업으로 구현한다(기술스택.md). 서버가 꺼져 있던 동안 지나간 납입일도 다음 실행에서 처리한다.
2. 오늘까지 납입일이 도래했고 아직 납입하지 않은 회차가 있으면 한 트랜잭션 안에서 저축예금 출금(transfer_out), 적금 입금(transfer_in), paid_count 1 증가를 처리한다. 상대 표시명은 "정기적금 n회차 자동이체"다.
3. 지정 저축예금의 잔액이 모자라면 그 회차는 **미납**으로 둔다(거래 기록 없음, paid_count 그대로). 적금 상세에 "n회차 미납"을 보이고, 배치가 매일 다시 시도해 잔액이 채워진 날 납입한다. 사용자가 수동으로 납입해도 된다.
4. 자동이체는 사용자가 요청하는 동작이 아니라서 S-08 간편비밀번호 확인이 없다. 개설할 때의 동의(5.1 5번)가 그 역할을 한다.
5. 자동이체는 계좌 상세(A-04, A-07)에서 켜고 끌 수 있다(`POST /api/accounts/{id}/auto-pay {enabled}`). 자동이체를 끈 적금은 배치가 건드리지 않는다.

**수동 납입** (자동이체를 껐거나 미납 회차가 있을 때)
1. 적금 계좌 상세(A-04)의 "납입하기" → A-07
2. 이번 달 납입 여부 확인(자동·수동 구분 없이 이미 납입했으면 "이번 달은 납입이 완료되었습니다"). 12회차 완료면 납입 불가
3. 지정 저축예금 잔액 확인 → "납입하기"
4. 처리: 한 트랜잭션 안에서 저축예금 출금(transfer_out), 적금 입금(transfer_in), paid_count 1 증가. 상대 표시명은 "정기적금 n회차 납입"
5. 적금 계좌 상세로 복귀

### 5.4 이체 (저축예금 간)

1. A-08에서 출금 저축예금 선택, 받는 계좌 선택(내 저축예금 / 계좌번호 입력 / 최근·자주 쓰는 계좌)
2. 계좌번호 입력 시 예금주 이름을 조회해 표시(없는 계좌, 해지 계좌, 예적금 계좌면 "이체할 수 없는 계좌입니다")
3. A-09에서 금액 입력. 잔액 초과, 0원, 1회 한도 초과, 1일 한도 초과(7.4의 합산 기준), 출금 계좌와 입금 계좌 동일 시 거부
4. A-10 확인. 여기서 S-08 간편비밀번호 확인이 필수다 (5분 안에 확인했으면 생략, 공통.md 4장). 확인 없이 요청하면 서버가 `403 PIN_VERIFICATION_REQUIRED`로 거부한다
5. 처리: 한 트랜잭션 안에서 출금 계좌 잔액 차감, 입금 계좌 잔액 증가, transactions 2건 기록. 중간 실패 시 전부 롤백
6. A-11 완료 화면. 최근 이체 목록 갱신

### 5.5 예적금 해지 (만기·중도)

1. 계좌 상세(A-04)의 "해지" → A-12
2. 서버가 오늘 기준으로 만기 여부를 판단하고 이자를 계산해 표시
   - 만기 이후: 약정 금리로 만기 이자
   - 만기 이전: 중도해지 금리로 이자, "중도 해지 시 약정 금리보다 낮은 이자가 적용됩니다" 안내
3. 받을 저축예금 확인(개설 시 지정한 계좌, 변경 가능) → 확인 문구 체크 → "해지하기"
   - "해지하기" 전에 S-08 간편비밀번호 확인이 필요하다 (5분 안에 확인했으면 생략, 공통.md 4장). 확인 없이 요청하면 `403 PIN_VERIFICATION_REQUIRED`
4. 처리: 한 트랜잭션 안에서 예적금 계좌의 원금을 저축예금으로 이체(예적금 계좌 transfer_out, 저축예금 transfer_in. 상대 표시명 "정기예금 만기해지" 등), 이자를 저축예금에 interest 1건으로 입금, 예적금 계좌 잔액 0, 해지된 계좌에 close(0원) 1건 기록, 상태 matured 또는 closed_early, closed_at 기록
5. 계좌 목록으로 이동. 해지 계좌는 "해지된 계좌 보기"로 분리
6. 만기 처리(ACC-13)는 같은 흐름이다. 만기일이 지난 계좌를 조회하면 "만기가 되었습니다. 해지하여 원리금을 받으세요" 안내만 띄우고, 입금은 사용자가 "해지하기"를 눌렀을 때만 일어난다. 시연용 "만기 도래 시뮬레이션" 버튼은 만기일을 어제로 바꾼다(개발 모드에서만 표시)

### 5.6 저축예금 해지

1. 계좌 상세(A-04)의 "해지" → A-12
2. 활성 예적금의 지정 저축예금이면 "연결된 예적금이 있어 해지할 수 없습니다" 후 종료. 해지 안 된 카드의 결제 계좌이면(`count_active_cards(account_id)` > 0) "연결된 카드가 있어 해지할 수 없습니다" 후 종료 (공통.md 8장)
3. 잔액이 있으면 받을 다른 저축예금 선택(없으면 "잔액을 0원으로 만든 뒤 해지해 주세요"). 잔액 0원이면 바로 확인 단계
4. 확인 문구 체크 → "해지하기" → 잔액 이전(이체와 같은 처리, transfer_out/transfer_in) → 해지된 계좌에 close(0원) 1건, 상태 closed, closed_at 기록, 대표계좌였으면 다른 저축예금으로 대표 이전
5. 계좌 목록으로 이동

## 6. 이자 계산 규칙

세전·단리·일할 계산으로 통일한다. 소수점은 원 단위 절사.

| 구분 | 계산 |
|---|---|
| 정기예금 만기 이자 | 원금 × 연금리 × 가입일수 / 365 |
| 정기적금 만기 이자 | 각 회차 납입금 × 연금리 × (만기일 − 납입일) / 365 의 합 |
| 중도해지 이자 | 위 식에서 연금리 대신 중도해지 금리(연 1.0%)를 쓰고, 종료일을 해지일로 둔다 |
| 현재까지 쌓인 이자 (조회용) | 만기 이자 식에 오늘을 종료일로 넣어 계산 |
| 저축예금 | 이자 지급 미구현. 연 0.1%는 표시만 |

- 계산 함수는 한 곳(backend/app/accounts/interest.py)에 두고 API·자연어 도구·해지 처리에서 같은 함수를 쓴다.
- 적금은 transactions의 transfer_in 기록(실제 납입일·금액)을 읽어 회차별로 계산한다. 미납 후 늦게 납입한 회차는 늦게 납입한 날부터 이자가 붙는다.

### 7.4 favorite_accounts (자주 쓰는 계좌)

| 컬럼 | 타입 | 제약 | 설명 |
|---|---|---|---|
| id | BIGINT | PK, GENERATED ALWAYS AS IDENTITY | |
| user_id | BIGINT | FK users.id, NOT NULL | |

- 이체·납입·해지 입금은 모두 출금 계좌의 transfer_out과 입금 계좌의 transfer_in 2건을 같은 트랜잭션에서 기록한다. 해지 이자는 입금 계좌에 interest 1건을 추가로 기록한다.
- `open`은 저축예금 개설 때만 기록한다(0원). 예적금 개설은 출금·입금 2건(transfer_out/transfer_in)만 기록한다. `close`는 계좌가 해지될 때 해지된 계좌에 0원으로 1건 기록한다.
- 최근 이체 계좌는 별도 테이블 없이 transactions의 transfer_out(사용자의 저축예금에서 나가고 상대가 저축예금인 것)을 최신순으로 조회해 만든다. 1일 이체 한도(1천만원)도 같은 기준으로 당일(KST)의 합계를 구해 검사한다. 적금 납입, 예적금 개설·해지는 상대가 저축예금이 아니거나 출금 계좌가 예적금이라 합계에 들어가지 않는다.
- 이번 범위에서는 카드 결제를 기록하지 않는다. transactions.type의 `card_payment`는 이름만 예약해 둔다 (공통.md 10장).
- PostgreSQL 기준 타입이다(공통.md 6장). 금액은 BIGINT(원 단위 정수), 금리는 NUMERIC(5,2), 시각은 TIMESTAMPTZ, 불리언은 BOOLEAN, 식별자는 BIGINT IDENTITY. 스키마는 Alembic 마이그레이션으로 관리한다.
- 이체·납입·해지의 "한 트랜잭션" 처리는 SQLAlchemy 세션 하나에서 출금·입금·거래 기록을 모두 수행한 뒤 commit하고, 예외 시 rollback한다. 잔액 갱신 시 `SELECT ... FOR UPDATE`로 두 계좌 행을 잠가 동시 이체를 막는다.
- 시드 데이터: products 3행. 사용자 id 1~4는 공통.md 7.1, 계좌는 삽입 순서대로 id를 고정해 부여하고 계좌번호는 공통.md 7.2의 값을 쓴다. user1의 계좌에 거래 내역 20건을 둔다. user3은 계좌 없음.

## 8. 자연어 입력과의 접점 (자연어 담당에게 전달)

| 의도 | 예시 문장 | 처리 방식 | 추가 질문 |
|---|---|---|---|
| acc.balance | "잔액 알려줘", "내 통장에 얼마 있어?" | 직접 실행. 저축예금 합계와 계좌별 잔액, 예적금은 원금 | 없음 |
| acc.list | "내 계좌 보여줘" | 직접 실행 + A-01 링크 | 없음 |
| acc.transactions | "이번 달 거래내역 보여줘", "최근 출금 내역" | 직접 실행(기간·유형 추출) + A-05 링크 | 계좌가 여러 개면 "어느 계좌요?" |
| acc.deposit | "10만원 입금해줘" | 확인 질문 후 직접 실행(시연용 입금, 저축예금만) | 금액 없으면 "얼마를 입금할까요?", 저축예금 여러 개면 "어느 계좌에요?" |
| acc.transfer | "하나한테 만원 보내줘", "생활비 계좌로 10만원 이체" | 받는 계좌·금액이 모두 있으면 확인 질문 후 실행. 하나라도 없으면 되묻기 | "얼마를 보낼까요?", "어느 계좌로 보낼까요?" |
| acc.pay_savings | "적금 납입해줘", "이번 달 적금 넣어줘" | 확인 질문 후 직접 실행(ACC-08). 이미 납입했으면 안내 | 없음 |
| acc.open | "적금 하나 만들고 싶어", "예금 가입할래", "통장 만들래" | 상품 종류를 추출해 A-03 링크. 불명확하면 A-02 링크. 조건 미충족이면 사유 안내 | 종류 불명확 시 "저축예금·정기예금·정기적금 중 어떤 걸 원하세요?" |
| acc.products (RAG) | "예금 금리 얼마야?", "적금 조건이 뭐야?", "이체 한도 얼마야?" | RAG로 상품 문서 3종과 계좌 이용 안내를 검색해 답변 + A-02 링크 | 없음 |
| acc.auto_pay | "적금 자동이체 꺼줘", "적금 자동이체 켜줘" | 확인 질문 후 직접 실행(자동이체 설정만 바꾸고 돈은 움직이지 않아 S-08 없음) | 적금이 하나뿐이라 대상 확인 없음 |
| acc.interest | "지금까지 이자 얼마 쌓였어?", "만기에 얼마 받아?" | 직접 실행(이자 계산 함수) | 예적금이 여러 개면 "어느 계좌요?" |
| acc.close_preview | "적금 지금 깨면 이자 얼마야?", "예금 중도해지하면 얼마 받아?" | 직접 실행(중도해지 예상 이자) + A-12 링크. 실제 해지는 화면에서만 | 대상 계좌 확인 |
| acc.close | "이 통장 없애줘", "계좌 해지하고 싶어" | 화면 링크(A-12)만 제공. 자연어로 직접 해지하지 않는다 | 대상 계좌 확인 |

- 위 의도는 Gemini 함수 호출(function calling) 도구로 구현한다. 계좌 파트가 11장의 함수(get_balance, list_accounts, get_transactions, deposit, transfer, pay_savings, set_auto_pay, open_account, get_interest, preview_close)를 제공하면 자연어 파트가 `google-genai`의 tools에 등록한다. user는 세션에서 서버가 주입하고 모델이 지정하지 못한다(공통.md 9.2).
- 입금·이체·납입처럼 돈이 움직이는 동작은 자연어에서 실행 전 반드시 확인 질문("user2님 계좌로 10,000원 보낼까요?")을 거친다. 도구는 1차 호출에서 "확인 필요"와 요약을 돌려주고, 사용자의 "응" 뒤 2차 호출에서 실행한다. 해지는 자연어로 실행하지 않는다.
- acc.products는 `search_docs(query)` 도구(pgvector 코사인 검색, 상위 5개 청크)로 처리한다. 상품 설명 md 3종과 계좌 이용 안내가 검색 대상이다.
- 계좌가 여러 개일 때 별명("생활비 계좌")이나 상품명("적금")으로 지정할 수 있게 함수에 넘긴다.
- 사용자가 문장에 타인 이름을 넣어도 본인 계좌 범위 안에서만 동작한다(회원,인증.md R8).
- 테스트 문장 세트: 위 예시 문장 + 맥락 유지용 연속 문장("하나한테 보내줘" → "얼마요?" → "만원" → 확인 → "응").
