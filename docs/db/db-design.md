# 통합 DB 테이블 설계

| 항목 | 내용 |
|---|---|
| 상태 | 기획 문서 기준으로 정렬 (2026-11-05). 회원·인증·계좌·카드는 아래 기획 문서가 정본이고, 가계부·대출은 이 문서가 정리본이다 |
| 기준 문서 | [공통.md](../common/공통.md) 6·7장, [회원,인증.md](../auth/회원,인증.md) 8장, [계좌.md](../account/계좌.md) 7장, [카드 backend-spec](../dev/card/backend-spec.md) 2장 |
| 관련 | [erd.md](erd.md) (같은 내용을 ERD로 그린 것), 구현은 `backend/app/models.py` |

이 문서는 도메인 간 연결과 가계부·대출처럼 아직 별도 기획 문서가 없는 부분을 한곳에 모은 것이다. 회원·인증·계좌·카드 컬럼은 요약만 적고 **기획 문서의 표가 정본**이다. 다르면 기획 문서를 따른다.

## 1. 공통 규칙 (공통.md 6장)

| 항목 | 규칙 |
|---|---|
| DB | PostgreSQL 17 + pgvector (기술스택.md) |
| 금액 | `BIGINT`(원). 소수 없음 |
| 일시 / 날짜 | `TIMESTAMPTZ`(UTC 저장) / `DATE`. "오늘" 경계는 KST |
| 회원·계좌 ID | `BIGINT IDENTITY`. 시드로 id를 고정하는 테이블(users, products, accounts)은 `GENERATED BY DEFAULT AS IDENTITY`로 만들고 시드 뒤에 시퀀스를 맞춘다. JSON은 숫자 |
| 파트 자체 ID | 그 파트가 정한다. 카드·가계부·대출은 `VARCHAR(40)` 접두어 + 시간순 값 (`card_…`, `tx_…`, `loan_…`). 사전순 = 생성순 |
| enum | `VARCHAR`(카드·가계부·대출은 + `CHECK`), 계좌·회원 문서는 `TEXT` |
| 공통 컬럼 | `created_at` 필수, 수정되는 테이블은 `updated_at` |
| FK | 같은 도메인 안에서는 FK. 도메인 간(`user_id`, `account_id`)은 **논리 참조**(FK 안 검). 단 계좌·회원 문서가 FK로 정한 곳(`accounts.user_id` 등)은 FK |
| 회원 테이블 | `users`. 모든 `user_id`는 `BIGINT` |
| 민감정보 | 카드 전체번호·카드 비밀번호는 저장 안 함. **계좌 암호(4자리)는 없다.** 본인 재확인은 간편비밀번호 6자리(`users.simple_pin_hash`, bcrypt). 계좌번호는 평문 저장(`1002-XXX-XXXXXX`)이고 다른 파트의 응답에는 마스킹만 나간다. 주민번호는 받지 않는다 |
| 세션 | 서명 쿠키라 세션 테이블이 없다 |

## 2. 도메인 한눈에 보기

```
[회원·인증] users 1─* devices

[계좌]     users 1─* accounts 1─* transactions
           products 1─* accounts,  accounts ─ linked_account_id ─ accounts (예적금 → 저축예금)
           users 1─* favorite_accounts
[공통]     idempotency_keys / audit_log

[카드]     card_products 1─* cards 1─* card_status_history
                               └─ 1─* card_transactions (cancel → original_id)
           card_applications → cards,  card_issue_quota
           cards.payment_account_id ··· accounts (논리)

[가계부]   budgets 1─* category_budgets
           card_transactions 1─1 ledger_tx_category (분류)
           planned_outflows, payment_attempts, ledger_settings(모드), ledger_goals
           chat_sessions 1─* chat_messages,  rag_documents (+ embedding)

[대출]     loan_application ─ consent_record / applicant_profile / suitability_result / evidence
                            ─ review_result / loan_terms / pricing / recommendation_log / explanation_record
           contract ─ repayment_schedule / collateral / disbursement
```

## 3. 회원·인증·계좌 (김연준)

### 3.1 `users` · `devices` (회원,인증.md 8장, 구현됨)

| 컬럼 | 타입 | NULL | 설명 |
|---|---|:--:|---|
| `id` | BIGINT | X | PK, IDENTITY(BY DEFAULT). 시드 사용자 id 1~4를 고정하려고 BY DEFAULT |
| `login_id` | VARCHAR(20) | X | UNIQUE. 소문자로 정규화해 저장 |
| `password_hash` | TEXT | X | bcrypt |
| `name` | VARCHAR(30) | X | |
| `birth_date` | DATE | X | 만 14세 이상 가입. 카드 신청 만 19세, 상품 가입 조건에 사용 (`get_age`) |
| `phone` | VARCHAR(11) | X | 숫자만 저장, 중복 허용 |
| `marketing_agree` | BOOLEAN | X | 선택 약관 |
| `simple_pin_hash` | TEXT | O | 간편비밀번호(6자리) bcrypt. 간편 로그인·2차 인증 공용. 미설정이면 NULL |
| `pin_set_at` | TIMESTAMPTZ | O | |
| `pin_failed_count` / `pin_locked_until` | INTEGER / TIMESTAMPTZ | X / O | 5회 실패 시 잠금(재설정으로만 해제, 먼 미래 값) |
| `failed_login_count` / `locked_until` | INTEGER / TIMESTAMPTZ | X / O | 비밀번호 5회 실패 시 10분 잠금 |
| `created_at` / `last_login_at` | TIMESTAMPTZ | X / O | |

`devices`: `id` BIGINT IDENTITY(ALWAYS) · `user_id` FK → users · `token_hash` UNIQUE(기기 쿠키 값의 SHA-256, 원문 저장 안 함) · `device_name` · `created_at` · `last_used_at` · `expires_at`(90일 슬라이딩) · `revoked_at`.

### 3.2 `products` (계좌.md 7.1, 3행 고정)

`id`(BY DEFAULT, 1 저축예금 · 2 정기예금 · 3 정기적금) · `type`(`checking`/`deposit`/`savings`) · `name` · `description` · `rate` NUMERIC(5,2) · `early_close_rate` · `min_amount` · `max_amount` · `min_months` · `max_months` · `max_per_user` · `requires_checking`.

### 3.3 `accounts` (계좌.md 7.2)

| 컬럼 | 타입 | 설명 |
|---|---|---|
| `id` | BIGINT | PK, IDENTITY(BY DEFAULT). 시드 id 1~6 고정 |
| `user_id` | BIGINT | FK → users |
| `product_id` | BIGINT | FK → products |
| `account_no` | TEXT | UNIQUE, `1002-XXX-XXXXXX` 평문. 다른 파트 응답에는 끝 4자리 마스킹(`****1234`)만 |
| `alias` | TEXT | 별명 |
| `balance` | BIGINT | 잔액(원). 예적금은 원금 누계. `CHECK (balance >= 0)` |
| `rate` | NUMERIC(5,2) | 개설 시점에 확정된 연금리 |
| `term_months` / `monthly_amount` / `payment_day` / `paid_count` | INTEGER / BIGINT / INTEGER / INTEGER | 예적금 가입 기간, 적금 월 납입액·납입일·납입 회차 |
| `auto_pay` | BOOLEAN | 적금 자동이체 여부. 기본 true |
| `linked_account_id` | BIGINT | FK → accounts. 예적금의 납입 출금·만기 입금 저축예금 |
| `opened_at` / `maturity_date` | DATE | 개설일 / 만기일 |
| `status` | TEXT | `active` / `matured` / `closed_early` / `closed` |
| `closed_at` | TIMESTAMPTZ | 해지 일시 |
| `is_primary` | BOOLEAN | 대표계좌 (저축예금만). 은행명은 컬럼이 아니라 API가 상수 `"AIM Bank"`를 내려준다 |

인덱스: `(user_id, status)`, `UNIQUE (user_id) WHERE is_primary`.

### 3.4 `transactions` (계좌 거래, 계좌.md 7.3)

`id` BIGINT · `account_id` FK · `type`(`open`/`deposit`/`transfer_in`/`transfer_out`/`interest`/`close`/`loan_disbursement`/`loan_repayment`, `card_payment`는 이름만 예약) · `amount` BIGINT(양수, open·close는 0) · `balance_after` · `counterparty_account_id` FK NULL · `counterparty_name` · `memo` · `ref_type` · `ref_id` · `created_at`. 이체·납입·해지는 출금 계좌 `transfer_out` + 입금 계좌 `transfer_in` 2건을 한 트랜잭션에서 기록한다. 인덱스 `(account_id, created_at DESC, id DESC)`.
예전 설계의 이름 `account_transactions`는 `transactions`로 바뀌었다. 카드 거래는 `card_transactions`로 따로 둔다.

> 대출 지급·상환(`loan_disbursement`/`loan_repayment` 유형)과 `ref_type`/`ref_id` 연결 컬럼은 계좌.md 7.3에 추가됐다(2026-11-06). 대출 거래는 `ref_type='loan'`, `ref_id=계약번호`로 찾는다.

### 3.5 `favorite_accounts` · `idempotency_keys` · `audit_log`

- `favorite_accounts`: `id`, `user_id` FK, `account_no`, `display_name`, `created_at`
- `idempotency_keys`: PK `(user_id, idem_key)` · `fingerprint` CHAR(64) · `response_status` SMALLINT NULL · `response_body` TEXT NULL · `created_at` · `expires_at`. 인덱스 `(expires_at)`. 카드 신청과 대출이 공용
- `audit_log` (대출 공통 감사 로그를 전 도메인 공용으로): `id`, `entity`, `entity_id`, `action`, `before` JSONB, `after` JSONB, `actor`, `at`. 인덱스 `(entity, entity_id, at)`. 대출의 위변조 탐지용 해시 체인 감사 로그는 이름이 겹치지 않게 `loan_audit_log`로 따로 둔다(6절)

## 5. 가계부 (박의혁) — 기획안 4절을 카드 모델에 맞춰 정리

### 5.1 기획안 초안과 달라진 점 (충돌 정리)

| 기획안 초안 | 통합안 | 이유 |
|---|---|---|
| `users` | `users` (회원,인증.md 8.1) | 카드·계좌와 같은 회원 테이블 사용 |
| `accounts` | 3.3 `accounts` 재사용 | 중복 방지, 대표계좌는 `is_primary` |
| `card_transactions`(user_id, category, approved_at, status, refund_of) | **카드 도메인 `card_transactions` 재사용** (취소 = `kind='cancel'` + `original_id`) + `ledger_tx_category` 분리 | 거래 원장은 카드가 소유. 가계부는 읽기 + 분류만 추가 |
| 거래 `status`(승인/거절/환불) | 거절은 `payment_attempts`로, 환불은 `cancel` 행으로 | 카드 거래에는 승인·취소만 존재 |
| `payment_attempts` | 유지 | 모의 결제 보류 근거 기록 |

### 5.2 테이블

**`ledger_tx_category`** — 카드 거래 분류 (사용자가 변경 가능)
`card_transaction_id` PK/FK → card_transactions · `user_id` · `category` VARCHAR(20) (`food`/`delivery`/`transport`/…) · `source` (`auto`/`user`) · `updated_at`. 인덱스 `(user_id, category)`.

**`budgets`** — 월 예산
`id` · `user_id` · `month` CHAR(7) `YYYY-MM` · `total_amount` BIGINT · `emergency_floor` BIGINT(최소 잔액) · `created_at`/`updated_at`. `UNIQUE (user_id, month)`.

**`category_budgets`**
`budget_id` FK · `category` · `amount` BIGINT. PK `(budget_id, category)`.

**`planned_outflows`** — 예정 출금 (카드대금·고정비)
`id` · `user_id` · `due_date` · `amount` · `type`(`card_bill`/`fixed`/`loan_repayment`) · `ref_type`/`ref_id`(카드 결제일 묶음·대출 상환일정 연결) · `status`(`planned`/`done`/`canceled`).

**`payment_attempts`** — 결제 전 확인(모의) 기록
`id` · `user_id` · `amount` · `category` · `result`(`allowed`/`held`) · `reason`(`MONTH_BUDGET`/`CATEGORY_BUDGET`/`BALANCE`) · `over_amount` · `card_transaction_id` NULL(허용 후 승인된 경우) · `created_at`. 인덱스 `(user_id, created_at)`.

**`ledger_settings`** — 말투 모드 저장
`user_id` PK · `mode`(`roast`/`basic`/`kind`/`numbers`) · `roast_level` SMALLINT · `updated_at`.

**`ledger_goals`** — 월 저축 목표
`id` · `user_id` · `month`(YYYY-MM) · `name` · `target_amount` · `created_at`. 회원당 월 1건(`UNIQUE(user_id, month)`). 모은 돈은 저장하지 않고 조회 시 `payment_attempts`의 이번 달 보류 합계로 계산한다.

**`chat_sessions`** · **`chat_messages`** — 가계부 대화와 홈 자연어 입력창이 함께 쓴다 (공통.md 9.3)
세션: `id`, `user_id`, `created_at`. 메시지: `id`, `session_id` FK, `role`(`user`/`assistant`), `content`, `intent`, `context_json` JSONB, `created_at`. 사용자별 대화 분리. 비밀번호·간편비밀번호는 남기지 않는다.

**`rag_documents`** — 상품·이용 안내 검색용
`id` · `source_url` · `title` · `version` · `chunk_text` · **`embedding vector(768)`** · `effective_date`. 출처·기준일 답변용. 임베딩 컬럼은 이 테이블에 더한다 (기술스택.md 5.3).

> 집계(월 순지출, 남은 예산, 결제 후 예상 잔액)는 **테이블에 저장하지 않고 조회 시 계산**한다 (기획안 "서버에서 다시 계산" 원칙).

### 6.2 대출 쪽 보완 제안 (원문에 없는 부분)

- 원문에 PK/FK/타입이 없어 구현에서 정했다: PK는 `application_id` 등 접두어+ULID(`lap_…`), `contract_no`는 업무용 번호(`LA-2026-NNNNNN`, 대환 `RA-…`)로 `UNIQUE`, 하위 테이블은 `contract_no` FK. 6.2의 `loanapp_…` 제안은 이 구현으로 대체한다.
- 대출 도메인에서 쓰는 금액은 모두 `BIGINT`(원), 금리는 `NUMERIC(6,4)`, JSON 컬럼은 `JSONB`.
- 대출 지급·상환은 `accounts`/`transactions`와 연결된다(`disbursement.account_id`·`account_txn_ref`, 거래의 `ref_type='loan'`·`ref_id=계약번호`). 거래 유형과 연결 컬럼은 계좌.md 7.3에 추가됐다.
- 가계부 `planned_outflows`가 `repayment_schedule`의 다음 회차를 읽도록 연결하면 "상환일 반영 후 예상 잔액"이 계산된다.

## 7. 도메인 간 연결 키

| 연결 | 방식 |
|---|---|
| 카드 ↔ 계좌 | `cards.payment_account_id` → `accounts.id` (논리), 은행명·마스킹은 스냅샷. 결제 계좌 후보는 저축예금이고 active인 계좌만. 계좌 해지 때 `count_active_cards(account_id)`로 확인 |
| 가계부 ↔ 카드 | `ledger_tx_category.card_transaction_id` FK, 청구 묶음은 카드 03 계산 결과를 `planned_outflows`로 반영 |
| 가계부 ↔ 대출 | `planned_outflows.ref_type='loan_repayment'`, `ref_id=repayment_schedule` |
| 대출 ↔ 계좌 | `disbursement.account_id`·`account_txn_ref`, `loan_account.debit_account_id`(논리 참조). 계좌 거래의 `ref_type='loan'`, `ref_id=계약번호`. 계좌 파트의 `loan_disburse`·`loan_repay`가 같은 트랜잭션에서 입출금 |
| 전 도메인 ↔ 회원 | `user_id` (논리 참조), **세션에서 얻은 값만 사용**(본문 값 불신) |
