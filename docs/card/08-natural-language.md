# 8. 자연어 연동 (카드)

[← 카드 기획서 개요](README.md)

홈의 자연어 입력창에서 카드 기능을 쓰는 방법을 정한다. 라우터·에이전트의 공통 규칙은 [공통 기획서 9장](../common/공통.md#9-자연어-연동-공통)이 원본이고, 이 문서는 **카드 에이전트가 어떤 도구를 갖고 어떤 문장을 어떻게 처리하는지**만 적는다.

## 1. 구조

```
홈 입력창 → 라우터 → 카드 에이전트 → 카드 서비스 함수 → 응답(텍스트 + 화면 링크 + 필요 시 S-08 호출 지시)
```

- 라우터가 문장을 보고 카드 도메인(`card.*`)이라고 판단하면 카드 에이전트로 넘긴다. 카드 에이전트는 아래 2절의 도구만 호출하고, 다른 도메인(계좌, 가계부, 대출) 기능은 호출하지 않는다.
- 도구는 카드 서비스 함수([백엔드 개발 명세](../dev/card/backend-spec.md)의 서비스 함수 계층)다. 화면 API가 부르는 함수와 같고, 같은 검증(소유권, 상태, 본인 재확인)을 거친다. 에이전트용 검증을 따로 만들지 않는다.
- 도구의 `user`는 서버가 세션에서 넣는다. 모델이 정하지 못한다.

## 2. 카드 에이전트의 도구

| 도구 | 서비스 함수 | 종류 | 본인 재확인 |
|------|-------------|:----:|:-----------:|
| `get_cards` | `list_cards` | 조회 | - |
| `get_card_detail(card_ref)` | `get_card` | 조회 | - |
| `get_card_transactions(card_ref?, from, to, merchant?, kind?)` | `list_transactions` | 조회 | - |
| `get_card_billing` | `get_billing_upcoming` | 조회 | - |
| `get_card_limit(card_ref)` | `get_limit` | 조회 | - |
| `check_card_terminate(card_ref)` | `check_terminate` | 조회 | - |
| `suspend_card(card_ref)` | `suspend_card` | 변경 | 필요 |
| `resume_card(card_ref)` | `resume_card` | 변경 | 필요 |
| `report_card_lost(card_ref, reason)` | `report_lost` | 변경 | 필요 |

- **카드 신청과 카드 해지는 도구가 없다.** 입력이 많고(약관, 카드 비밀번호, 주소) 되돌릴 수 없는 동작이라 화면 링크만 준다 (계좌.md 8장의 "해지는 화면 링크만"과 같은 원칙).
- **`card_ref` 정하기**: 카드 이름, 끝 4자리, "신용카드"/"체크카드", "정지된 카드"처럼 문장에서 뽑은 단서로 **본인 카드** 중에서 찾는다.
  - 한 장으로 정해지면 그 카드로 진행한다.
  - 여러 장이면 되묻는다. 예: "어느 카드요? AIM 신용카드(2222), AIM 신용카드(3333)가 있어요."
  - 해지된 카드는 문장에 "해지된"이라고 했을 때만 대상에 넣는다.
  - 본인 카드 중에 없으면(타인의 카드, 없는 번호) "해당 카드를 찾을 수 없어요"라고만 답한다. 타인의 카드라는 사실을 알려주지 않는다 (404와 같은 원칙).

## 3. 의도

의도 이름은 `card.<동작>`이다 (공통 9.1).

| 의도 | 예시 문장 | 처리 | 추가 질문 |
|------|-----------|------|-----------|
| card.list | "내 카드 보여줘", "카드 몇 장 있어?" | 직접 실행(`get_cards`). 카드 이름·종류·상태 요약 + `/cards` 링크 | 없음 |
| card.detail | "신용카드 정보 알려줘", "2222 카드 결제일 언제야?" | 직접 실행(`get_card_detail`) + 해당 카드 링크 | 카드가 여러 장이면 "어느 카드요?" |
| card.transactions | "이번 달 카드 사용내역", "10월에 스타벅스에서 얼마 썼어?" | 직접 실행(`get_card_transactions`). 기간·가맹점·카드를 문장에서 뽑는다. 합계와 건수 요약 + `/cards/transactions` 링크 | 기간이 없으면 "언제부터 언제까지 볼까요?" |
| card.billing | "이번 달 카드값 얼마야?", "카드 결제일이 언제야?" | 직접 실행(`get_card_billing`). 결제일별 금액과 결제 계좌 잔액 부족 여부 + `/cards/billing` 링크 | 없음 |
| card.limit | "신용카드 한도 얼마 남았어?", "체크카드 하루 한도가 얼마야?" | 직접 실행(`get_card_limit`) + 해당 카드 한도 링크 | 카드가 여러 장이면 "어느 카드요?" |
| card.suspend | "카드 잠깐 정지해줘", "2222 카드 막아줘" | **확인 질문 → 본인 재확인(S-08) → 실행** (4절) | 카드를 정하지 못하면 "어느 카드요?" |
| card.resume | "카드 정지 풀어줘", "3333 카드 다시 쓸래" | 확인 질문 → S-08 → 실행 | 카드를 정하지 못하면 "어느 카드요?" |
| card.report_lost | "카드 잃어버렸어", "카드 도난당했어" | 확인 질문 → S-08 → 실행. 되돌릴 수 없다고 확인 질문에 적는다 | 카드를 정하지 못하면 "어느 카드요?", 사유를 모르면 "분실인가요, 도난인가요?" |
| card.terminate_check | "신용카드 해지할 수 있어?", "카드 해지하면 남은 결제금액이 있어?" | 직접 실행(`check_card_terminate`). 해지 가능 여부와 미결제 금액·첫 결제일 | 카드가 여러 장이면 "어느 카드요?" |
| card.terminate | "카드 해지해줘" | **실행하지 않는다.** 해지 화면 링크(`/cards/:cardId/terminate`)만 준다. 카드를 정할 수 있으면 `check_card_terminate` 결과를 한 줄로 함께 알려준다 | 카드를 정하지 못하면 "어느 카드요?" |
| card.apply | "카드 새로 만들고 싶어", "체크카드 하나 더 신청할래" | **실행하지 않는다.** `/cards/apply` 링크만 준다. 문장에 신용/체크가 있으면 안내 문구에만 반영한다 | 없음 |
| card.faq (RAG) | "카드 한도는 어떻게 정해져?", "분실 신고하면 되돌릴 수 있어?", "결제일은 언제까지 정해?" | RAG로 카드 이용 안내 문서(5절)를 검색해 답변. 로그인하지 않아도 답한다 | 없음 |

- 카드를 새로 만드는 문장에서 보유 한도(종류별 3장)나 신청 자격(만 19세) 때문에 신청할 수 없는 경우에도 에이전트는 판단하지 않고 신청 화면으로 보낸다. 신청 화면의 자격 확인이 사유를 보여준다.
- 이미 그 상태인 카드에 같은 요청을 하면(정지된 카드를 정지) 실행하지 않고 현재 상태를 알려준다. 허용되지 않는 상태(분실 카드 정지 등)도 같다. ("이미 정지된 카드예요", "분실 신고된 카드는 정지할 수 없어요")

## 4. 확인 질문과 본인 재확인 흐름

정지·해제·분실 신고는 카드 상태를 바꾸므로 [공통 9.2](../common/공통.md#92-모든-에이전트가-지키는-규칙)의 확인 질문과 본인 재확인(S-08)을 모두 거친다.

```
사용자  "카드 잠깐 정지해줘"
에이전트 (카드가 여러 장이면) "어느 카드요?"                    ← 되묻기
사용자  "2222"
에이전트 "AIM 신용카드(2222)를 일시정지할까요? 정지하면 결제와 이용이 막히고, 나중에 해제할 수 있어요."
        (도구 1차 호출 → { status: "confirm_required", summary })
사용자  "응"
에이전트 (도구 2차 호출) 5분 안에 확인하지 않았으면 → { status: "pin_verification_required" }
프론트   S-08 간편비밀번호 확인 화면을 띄운다 (채팅에서 비밀번호를 받지 않는다)
        통과 → 같은 실행을 다시 요청
에이전트 "AIM 신용카드(2222)를 일시정지했어요." + 해당 카드 링크
```

| 상황 | 동작 |
|------|------|
| 확인 질문에 "아니"/"취소" | 실행하지 않고 "취소했어요"라고 답한다. 카드 상태는 그대로다 |
| 5분 안에 S-08을 이미 통과했다 | S-08을 건너뛰고 바로 실행한다 |
| S-08에서 취소했다 | 실행하지 않는다. "본인 확인을 취소해서 실행하지 않았어요" |
| S-08에서 5회 틀려 잠겼다 | 실행하지 않는다. "간편비밀번호가 잠겼어요. 로그인 화면에서 재설정해 주세요" |
| S-08을 통과했지만 그 사이 카드 상태가 바뀌어 `409`가 났다 | 현재 상태를 알려준다. S-08은 5분 안이면 다시 묻지 않는다 |
| 분실 신고 확인 질문 | "분실 신고는 되돌릴 수 없어요. AIM 신용카드(2222)를 분실 신고할까요?"처럼 되돌릴 수 없다는 점을 적는다 |
| 분실 신고가 끝난 뒤 | 재발급은 안내 문구만 준다 (README 6절 4번). 별도 링크는 없다 |
| 사용자가 채팅에 간편비밀번호를 입력했다 | 사용하지 않는다. "보안을 위해 채팅에는 비밀번호를 입력하지 마세요. 확인 화면에서 입력해 주세요"라고 안내한다 |

**서버 처리**
- 1차 호출은 실행하지 않고 **대기 동작**(동작, `card_id`, 분실 사유)을 세션에 저장한다.
- 사용자의 "응" 뒤에는 모델이 인자를 다시 만들지 않고 서버가 세션의 대기 동작을 실행한다. 모델이 확인 후에 다른 카드로 바꾸는 일을 막기 위해서다.
- 대기 동작은 취소, 새로운 의도, 로그아웃·만료로 지운다. 5분이 지난 대기 동작은 다시 확인 질문부터 시작한다.
- 대기 동작과 대화 기록에 간편비밀번호 값은 없다.

## 5. RAG 검색 대상 문서

카드 담당이 아래 2종을 만들어 RAG 담당에게 넘긴다. 내용은 이 기획서의 규칙에서 가져오고, 문서에 없는 숫자나 규칙을 새로 만들지 않는다.

| 문서 | 담을 내용 | 근거 |
|------|-----------|------|
| 카드 상품 설명 | 체크카드·신용카드 종류, 신용카드 한도 부여 방식(연소득 구간별 고정표, 1,000만 원 미만 거절), 결제일 선택(1~28일, 기본 25일), 종류별 최대 3장 보유, 신청 자격(만 19세 이상, 신용카드), 신청 후 바로 사용 가능 | README 6절, [06-issuance.md](06-issuance.md) |
| 카드 이용 안내 | 일시정지·해제 방법, 분실 신고(되돌릴 수 없음, 재발급 안내), 청구 이용기간(전월 1일~말일)과 결제일 계산, 이용 금액·잔여 한도, 해지 조건(미결제 금액 0원), 해지 후 이용내역 조회 | README 6절, 00 6절, [04](04-lost-suspend.md), [05](05-limit.md), [07](07-termination.md) |

- 카드 상품 설명과 `GET /card-products`의 상품 설명 문구는 같은 원본에서 만든다.

## 6. 로그인하지 않았거나 세션이 만료된 경우

[공통 9.2](../common/공통.md#92-모든-에이전트가-지키는-규칙)의 인증 우선 규칙을 따른다.

- 의도를 분류하기 전에 세션의 user를 확인한다. 로그인하지 않았으면 카드 의도 중 `card.faq`만 답하고, 나머지는 "로그인 후 이용할 수 있어요" + 로그인 링크로 응답한다. 카드 함수는 호출하지 않는다.
- 세션이 만료됐으면 "로그인 시간이 만료되었어요. 다시 로그인해 주세요." + 로그인 링크로 응답한다. 대화 맥락은 사라진 것으로 안내한다.
- 간편비밀번호를 설정하지 않은 상태면(`403 PIN_SETUP_REQUIRED`) 설정 화면(S-07) 링크로 안내한다.

## 7. 테스트 문장 (공통 세트에 포함)

기준 데이터(00 10절, 오늘 = 2026-11-04)로 확인한다. 로그인 사용자는 user1이다.

| 번호 | 상태 | 문장 | 기대 동작 |
|------|------|------|-----------|
| NL-01 | 인증 | "내 카드 보여줘" | 보유 카드 요약(해지 카드 제외) + `/cards` 링크 |
| NL-02 | 인증 | "이번 달 카드값 얼마야?" | 결제일 2026-11-25에 945,000원(계좌 1로 45,000원, 계좌 2로 900,000원), 계좌 2는 잔액이 부족하다는 안내 + `/cards/billing` 링크 |
| NL-03 | 인증 | "10월에 스타벅스에서 얼마 썼어?" | 승인 12,000원, 취소 12,000원, 순 사용 0원 요약 + `/cards/transactions` 링크 |
| NL-04 | 인증 | "신용카드 한도 얼마 남았어?" | 신용카드가 여러 장이라 "어느 카드요?" 되묻기 |
| NL-05 | 인증 (NL-04 이어서) | "2222" | 맥락을 유지해 `card_002` 한도 요약(총 3,000,000원, 이용 1,208,000원, 잔여 1,792,000원) |
| NL-06 | 인증 | "카드 잠깐 정지해줘" | 어느 카드인지 되묻기 → "2222 신용카드" → 확인 질문 → "응" → S-08 → 정지 완료 안내. `card_002`가 `suspended` |
| NL-07 | 인증 | "카드 잃어버렸어" | 어느 카드인지 되묻기 → 확인 질문(되돌릴 수 없다는 문구) → "응" → S-08 → 분실 처리와 재발급 안내 문구 |
| NL-08 | 인증 | "3333 카드 정지 풀어줘" | 확인 질문 → "응" → S-08 → `card_003`이 `active`가 됨 |
| NL-09 | 인증 | "카드 해지해줘" | 실행하지 않고 해지 화면 링크. 카드를 정하면 해지 가능 여부를 한 줄로 안내 |
| NL-10 | 인증 | "2222 카드 해지할 수 있어?" | 해지 불가, 미결제 1,208,000원, 첫 결제일 2026-11-25 안내 |
| NL-11 | 인증 | "카드 새로 만들고 싶어" | `/cards/apply` 링크만. 신청을 실행하지 않음 |
| NL-12 | 인증 | "9000 카드 정지해줘" (user2의 카드) | "해당 카드를 찾을 수 없어요". 정지되지 않음 |
| NL-13 | 인증 | NL-06에서 확인 질문에 "아니" | "취소했어요". 카드 상태 그대로 |
| NL-14 | 인증 | "카드 정지할게, 비밀번호는 135792야" | 채팅의 비밀번호를 사용하지 않고 S-08 안내. chat_messages와 대기 동작에 값 없음 |
| NL-15 | 인증 | NL-06에서 S-08을 통과한 뒤 6분 후 "3333 카드 정지 풀어줘"에 "응" | 5분이 지나 S-08을 다시 띄움 |
| NL-16 | 인증 | "4444 카드 정지해줘" (분실 카드) | 실행하지 않고 "분실 신고된 카드는 정지할 수 없어요" 안내 |
| NL-17 | 미인증 | "내 카드 보여줘" | 로그인 안내 + 로그인 링크. 카드 조회 함수가 호출되지 않음 |
| NL-18 | 미인증 | "분실 신고하면 되돌릴 수 있어?" | RAG로 답변(되돌릴 수 없음) |
| NL-19 | 만료 | (30분 방치 후) "카드값 얼마야?" | 만료 안내 + 로그인 링크 |

## 8. 구현 메모

- 에이전트는 서비스 함수를 직접 호출한다 (같은 서버). 화면 API(HTTP)를 경유하지 않는다.
- 응답 모양은 `{ text, links: [{ label, path }], action? }`이다. 본인 재확인이 필요하면 `action: "pin_verification_required"`를 주고, 프론트가 S-08을 띄운다 ([공통 9.2](../common/공통.md#92-모든-에이전트가-지키는-규칙)).
- 금액·날짜는 화면과 같은 표기(`1,234,000원`, `2026.11.04`)로 답한다. 카드 번호는 끝 4자리만 말한다.
- 대화 기록(chat_messages)에 카드 전체 번호, 간편비밀번호, 카드 비밀번호를 남기지 않는다.
