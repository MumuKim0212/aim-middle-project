# 5. 한도 조회

[← 카드 기획서 개요](README.md) · 경로: `/cards/limit` (카드 선택), `/cards/:cardId/limit` (한도 화면)

## 목적

카드의 한도와 남은 한도를 확인한다.

## 범위

- **조회만** 한다. 일시 한도 상향, 한도 하향, 영구 한도 변경 등 한도 변경 기능은 만들지 않는다.
- 이 화면의 **이용 금액** 계산은 [공통 계산 기준 6절](00-api-common.md#6-금액-계산-기준-공통)이며, 카드 상세([01](01-card-list-detail.md))와 해지 가능 판정([07](07-termination.md))이 같은 기준을 쓴다.

## 사용자 시나리오

- 큰 결제를 하기 전에 남은 한도를 확인한다.
- 체크카드의 1회·1일 한도를 확인한다.

## 화면 구성

### 카드 선택 (`/cards/limit`)

- 카드 상세에서 들어오면 이 선택 화면을 거치지 않고 곧바로 그 카드의 한도 화면이 열린다.
- 메뉴의 **한도 조회**로 들어오면 `/cards/limit`에서 카드 선택 목록을 먼저 보여준다. 카드를 고르면 `/cards/:cardId/limit`로 이동한다.
- 목록은 해지되지 않은 카드(`GET /cards`)다. 항목에는 카드 이름, 종류 뱃지, 끝 4자리, 상태 뱃지를 보여준다. 일시정지·분실 카드도 고를 수 있다.
- 목록에 카드가 없으면 "조회할 수 있는 카드가 없습니다" 안내와 **카드 신청** 버튼을 보여준다.

### 한도 화면 (`/cards/:cardId/limit`)

| 카드 종류 | 표시 항목 |
|-----------|-----------|
| 신용 | 총 한도, 이용 금액, 잔여 한도, 이용 비율 막대 |
| 체크 | 1회 한도, 1일 한도 |

- 화면 상단에 카드 요약(이름, 종류, 끝 4자리, 상태 뱃지)을 보여준다.
- 한도를 바꾸는 버튼이나 입력은 두지 않는다.
- 이용 비율 막대는 `이용 금액 ÷ 총 한도`다. 100%를 넘으면 막대는 가득 찬 상태로 그린다.

## 기능 규칙

1. **총 한도**: 신용카드는 Card의 `creditLimit`이다. 신청 때 부여된 한도([06-issuance.md](06-issuance.md))가 그대로 들어간다.
2. **이용 금액**: 아직 결제되지 않은 이용액이다. 결제일 기준 청구 주기별 청구액 중 아직 결제되지 않은 주기(`P ≥ 오늘`)의 합이며, 계산 방법은 [공통 6.5](00-api-common.md#65-이용-금액잔여-한도-신용카드)가 정본이다.
3. **잔여 한도** = 총 한도 − 이용 금액. 0 아래로 내려가면 0원으로 표시한다.
4. **체크카드 한도**: Card의 `debitLimit`(1회·1일) 값을 그대로 보여준다. 이용 금액·잔여 한도는 없다.
5. **접근 가능한 카드**: 정상·일시정지·분실 카드는 조회할 수 있다. 해지된 카드는 이 화면에 들어올 수 없다.
6. 존재하지 않는 `cardId`로 열면 "카드를 찾을 수 없습니다" 안내와 목록으로 돌아가는 버튼을 보여준다.

## 상태별 화면

| 상태 | 처리 |
|------|------|
| 로딩 | 한도 영역 로딩 표시 |
| 불러오기 실패 | "한도 정보를 불러오지 못했습니다" + 다시 시도 버튼 |
| 해지된 카드 | "해지된 카드입니다" + 목록으로 가는 버튼 |

## 데이터

- Card의 `creditLimit`, `debitLimit`과 Transaction으로 계산한다. 별도 한도 모델은 없다.
- 목업 단계에서는 카드마다 한도 값을 고정해 둔다.

## API 명세

공통 규칙은 [00-api-common.md](00-api-common.md), 이용 금액 계산은 [공통 6절](00-api-common.md#6-금액-계산-기준-공통)을 따른다. 예시는 [목업 기준표](00-api-common.md#10-목업-데이터-기준표) 값이다.

### `GET /api/cards/{cardId}/limit` — 한도 조회

응답 `200` (신용카드 `card_002`, 오늘 2026-11-04)

```json
{
  "cardId": "card_002",
  "type": "credit",
  "status": "active",
  "credit": { "total": 3000000, "used": 1208000, "remaining": 1792000, "usageRate": 40.3 },
  "debit": null
}
```

응답 `200` (체크카드 `card_001`)

```json
{
  "cardId": "card_001",
  "type": "debit",
  "status": "active",
  "credit": null,
  "debit": { "perTx": 1000000, "perDay": 3000000 }
}
```

| 필드 | 설명 |
|------|------|
| `status` | 카드 상태. 화면 상단 뱃지용 |
| `credit` | 신용카드일 때만, 체크카드는 `null` |
| `credit.total` | 총 한도 (`creditLimit`) |
| `credit.used` | 이용 금액. [공통 6.5](00-api-common.md#65-이용-금액잔여-한도-신용카드)의 `used` |
| `credit.remaining` | `max(0, total − used)` |
| `credit.usageRate` | `min(100, round(used ÷ total × 100, 소수 첫째 자리))`, 0~100 사이 숫자 |
| `debit` | 체크카드일 때만, 신용카드는 `null` |
| `debit.perTx`, `debit.perDay` | 1회·1일 한도 (고정값) |

- 카드 상세(`GET /cards/{cardId}`)의 `limit`과 이 응답의 `credit`은 같은 계산이라 값이 항상 같다.
- 한도를 바꾸는 API는 없다.

### 오류

| HTTP | code | 언제 | `details` |
|:----:|------|------|-----------|
| 401 | `LOGIN_REQUIRED` / `SESSION_EXPIRED` | 로그인 안 함 / 세션 만료 | - |
| 403 | `PIN_SETUP_REQUIRED` | 간편비밀번호를 아직 설정하지 않음 | - |
| 404 | `CARD_NOT_FOUND` | 없는 카드이거나 남의 카드 | - |
| 409 | `CARD_STATE_INVALID` | 해지된 카드 | `currentStatus: "terminated"`, `allowedStatuses: ["active", "suspended", "lost"]` |

## 예외·오류 처리

| 상황 | API 결과 | 화면 동작 |
|------|----------|-----------|
| 이용 금액이 총 한도 이상 | `remaining: 0`, `usageRate: 100` | 막대를 가득 채우고 "한도를 모두 사용했습니다" |
| 이용 금액 0원 | `used: 0`, `usageRate: 0` | 막대는 비어 있고 "사용한 한도가 없습니다" |
| 해지된 카드로 접근 (주소 직접 입력 등) | `409 CARD_STATE_INVALID` | "해지된 카드입니다" + 목록으로 버튼 |
| 없는 카드, 남의 카드 | `404` | "카드를 찾을 수 없습니다" + 목록으로 버튼 |
| 일시정지·분실 카드 | `200` | 정상 조회. 상단에 상태 뱃지 |
| 체크카드 | `200`, `credit: null` | 1회·1일 한도 두 줄만 표시 (이용 금액·막대 없음) |
| 서버 오류·10초 초과 | `5xx` | "한도 정보를 불러오지 못했습니다" + 다시 시도 |
| 시간이 지나 결제일이 지남 (같은 화면을 오래 열어 둠) | 다음 조회에서 `used`가 줄어듦 | 화면에 다시 들어올 때 재조회. 자동 갱신은 하지 않음 |

## 프론트 구현 메모

- 라우트: `/cards/limit` (카드 선택, 04와 공용 `CardPickerPage`), `/cards/:cardId/limit` (한도 화면)
- 컴포넌트: `LimitPage`, `CardSummaryHeader`, `CreditLimitPanel`(총 한도, 이용 금액, 잔여 한도, `UsageBar`), `DebitLimitPanel`
- `UsageBar`는 `usageRate`를 그대로 폭(%)에 쓰고, 색만으로 상태를 전하지 않도록 퍼센트 숫자를 같이 보여준다. (`role="progressbar"`, `aria-valuenow`)
- 한도 변경 버튼이나 입력창은 어디에도 두지 않는다.

## 완료 기준

- [ ] 신용카드는 총/이용/잔여 한도와 이용 비율 막대가 보인다
- [ ] 체크카드는 1회/1일 한도만 보인다
- [ ] 이용 금액·잔여 한도가 카드 상세 화면의 값과 같다
- [ ] 한도를 바꾸는 버튼이 어디에도 없다
- [ ] 해지된 카드로는 이 화면이 열리지 않는다
