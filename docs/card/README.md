# 카드 기능 기획서 (개요)

| 항목 | 내용 |
|---|---|
| 담당 | 김경민 |
| 대상 | AIM Bank 모바일 웹 |
| 작성일 | 2026-11-04 (2026-11-05 공통 기획서·자연어 연동 반영) |
| 상태 | 확정 (본인 재확인 방식 등 10절 항목은 팀 확인 필요) |
| 디자인 기준 | 우리은행 모바일웹(우리WON뱅킹) 금융상품 > 카드 (2.1절) |
| 관련 문서 | [공통 기획서](../common/공통.md), [회원,인증.md](../auth/회원,인증.md), [계좌.md](../account/계좌.md) |

여러 파트가 함께 지키는 규칙(화면 폭, 인증 방식, 본인 재확인, 오류 응답 형식, 시드)은 [공통 기획서](../common/공통.md)를 따른다. 이 문서와 다르면 공통 기획서가 우선이다.

## 1. 목적과 범위

> 과제 조건: "계좌, 카드 등 은행의 기본적인 기능들을 클론코딩한다." 카드는 조회·신청·긴급 업무까지를 필수 범위로 한다.

로그인한 고객이 자신의 카드를 조회하고, 이용·청구 내역을 확인하며, 분실·정지·해지 같은 긴급·변경 업무를 모바일 웹에서 처리한다. 홈의 자연어 입력창으로도 같은 기능을 쓸 수 있다.

**범위 안**
- 카드 7개 기능: 목록·상세, 이용내역, 청구·결제 예정, 분실·정지·재개, 한도 조회, 신규 발급·신청, 해지
- 자연어 연동: 홈 입력창 → 라우터 → 카드 에이전트가 위 기능을 호출 ([08-natural-language.md](08-natural-language.md))

**카드 파트가 다른 파트에 제공하는 것**
- 카드 서비스 함수 (목록, 이용내역, 청구, 한도, 정지·해제·분실, 해지 확인 등. 화면 API와 자연어 에이전트가 같은 함수를 쓴다)
- `count_active_cards(account_id)`: 계좌 해지 때 활성 카드가 있는지 확인 (계좌 파트가 호출)
- 카드 이용 안내 문서 2종 (RAG 검색 대상, [08](08-natural-language.md) 5절)

**범위 밖 (이번에 만들지 않음)**
- 재발급 처리, 카드 수령 후 사용 등록(활성화), 신청 이력 목록
- 실제 결제 승인 처리와 결제 실행 (이용내역과 청구액은 목업 데이터로 표시). 그래서 카드 대금·체크카드 사용이 계좌 거래내역에 기록되지 않는다 (계좌.md가 제안한 `card_payment` 거래 기록은 쓰지 않는다. 10절)
- 한도 변경(일시 상향, 하향, 영구 변경), 현금서비스, 해외 이용 설정
- 카드 상품 안내 화면(비로그인 공개). 신청 1단계의 상품 선택이 그 역할을 한다 (우리WON뱅킹의 상품설명·약관 항목은 신청 화면의 약관 보기로 대신)

## 2. 기능 목록

| # | 기능 | 한 줄 설명 | 상세 문서 | 제안 경로 |
|---|------|-----------|-----------|-----------|
| 1 | 내 카드 목록·상세 | 보유 카드, 종류(신용/체크), 결제 계좌, 한도 확인 | [01-card-list-detail.md](01-card-list-detail.md) | `/cards`, `/cards/:cardId` |
| 2 | 이용내역 조회 | 기간·가맹점별 조회, 승인/취소 구분 | [02-transactions.md](02-transactions.md) | `/cards/transactions` |
| 3 | 청구·결제 예정 금액 | 이번 달 결제 예정액, 결제일, 결제 계좌 | [03-billing.md](03-billing.md) | `/cards/billing` |
| 4 | 카드 분실·정지·재개 | 분실 신고, 일시 정지와 해제 | [04-lost-suspend.md](04-lost-suspend.md) | `/cards/security` (카드 선택), `/cards/:cardId/security` |
| 5 | 한도 조회 | 신용 한도·이용 금액·잔여 한도, 체크카드 1회·1일 한도 확인 | [05-limit.md](05-limit.md) | `/cards/limit` (카드 선택), `/cards/:cardId/limit` |
| 6 | 카드 신규 발급·신청 | 체크·신용카드 신청, 심사, 발급 결과 확인 | [06-issuance.md](06-issuance.md) | `/cards/apply` |
| 7 | 카드 해지 | 미결제 금액 확인 후 카드 해지 | [07-termination.md](07-termination.md) | `/cards/:cardId/terminate` |
| 8 | 자연어 연동 | 홈 입력창에서 카드 기능 호출, 확인·본인 재확인 규칙 | [08-natural-language.md](08-natural-language.md) | (화면 없음. 홈 입력창) |

경로는 [공통 기획서](../common/공통.md) 2장의 URL 규칙(소문자 복수형)을 따른다. 하단 탭의 **카드**는 `/cards`(내 카드 목록)로 연결한다.

햄버거 메뉴의 카드 항목 5개(1~5번)가 각 경로로 연결된다. 카드를 하나 골라야 하는 4·5번은 메뉴에서 들어올 때 먼저 `/cards/security`, `/cards/limit`의 카드 선택 목록을 보여주고, 카드 상세에서 들어올 때는 선택 없이 그 카드의 화면으로 바로 간다. 2번은 화면 안의 카드 필터로 고르고, 3번은 전체 신용카드가 대상이다. 6번은 내 카드 목록의 **카드 신청** 버튼, 7번은 카드 상세의 **카드 해지** 링크에서 들어가며 메뉴에는 넣지 않는다. 경로가 겹쳐 보이는 `/cards/:cardId`와 `/cards/transactions`, `/cards/billing`, `/cards/apply`, `/cards/security`, `/cards/limit`은 **고정 경로가 우선**한다 (카드 ID가 이 단어와 같을 수 없다).

**개발 문서 읽는 순서**: 먼저 [공통 기획서](../common/공통.md)와 [00-api-common.md](00-api-common.md)(API 공통 규칙, 오류 코드, 본인 재확인, 상태 전이, 금액 계산 기준, 목업 기준 데이터)를 읽고, 만들 기능의 상세 문서(01~08)를 본다. 각 상세 문서에는 API 명세, 입력 검증, 예외·오류 처리, 프론트 구현 메모, 테스트 시나리오가 들어 있다. DB 설계·서버 구현 규칙·프론트 구조와 목업 제어 같은 개발 명세는 기획서와 분리해 [백엔드 개발 명세](../dev/card/backend-spec.md), [프론트 개발 명세](../dev/card/frontend-spec.md)에 둔다.

### 2.1 참고한 실제 앱

`docs/references/card/`의 우리WON뱅킹 스크린샷 2장이 기준이다.

| 화면 | 확인한 것 | 반영 |
|------|-----------|------|
| 금융상품 > 카드 (`금융상품_카드.png`) | 상단 탭(펀드·대출·보험·사업자·카드), 상품 카드별 큰 제목 + 파란 테두리 버튼(계좌개설 + 체크카드, 신청하기), 얇은 구분선 목록 | 내 카드 목록과 카드 신청 진입 버튼의 모양. 신청 1단계 상품 선택도 같은 카드형 목록으로 한다 |
| 상품 상세 (`금융상품_카드_WON통장.png`) | 상품 소개 문구, 상품설명·금리보기·약관 및 설명서 항목(오른쪽 화살표), 하단 고정 버튼 둘(다른 상품 보기 / 가입하기) | 신청 화면의 약관 보기 항목과 하단 고정 버튼(이전 / 다음) 배치 |

- 위 설명은 스크린샷에서 직접 본 요소만 적었다. 실제 앱의 단계 수나 입력 항목은 확인하지 못했다.
- 우리WON뱅킹 상품 화면의 자유입출금통장 + 체크카드 동시 발급은 계좌 파트와 연결이 필요해 이번 범위에서 제외한다.

## 4. 공통 데이터 모델

프론트 먼저 구현하므로 아래 형태의 목업 데이터를 `frontend/src/features/card/mock/` 에 둔다. 백엔드가 생기면 같은 형태의 API 응답으로 교체한다.

**Card**

| 필드 | 타입 | 설명 |
|------|------|------|
| id | string | 카드 식별자 |
| name | string | 카드 이름 (예: AIM 체크카드) |
| type | `credit` \| `debit` | 신용 / 체크 |
| numberMasked | string | 표시용 번호. 끝 4자리만 노출 (`****-****-****-1234`) |
| expiry | string | 유효기간 `MM/YY` |
| status | `active` \| `suspended` \| `lost` \| `terminated` | 정상 / 일시정지 / 분실 / 해지 |
| issuedAt | string | 발급일 `YYYY-MM-DD` |
| paymentAccount | { accountId, bankName, accountMasked } | 결제 계좌 (계좌 번호는 끝 4자리만 노출. `accountId`는 계좌 파트의 숫자 ID) |
| paymentDay | number \| null | 결제일 (신용만, 1~28, 기본 25. 신청 시 고객이 정함) |
| creditLimit | number \| null | 신용 한도 (신용만) |
| debitLimit | { perTx, perDay } \| null | 1회·1일 한도 (체크만) |
| suspendedAt | string \| null | 일시정지 일시 (정지 중일 때만) |
| lostAt / lostReason | string \| null / `lost` \| `stolen` \| null | 분실 신고 일시·사유 (분실 신고한 카드만. 이후 해지해도 유지) |
| terminatedAt / terminatedReason | string \| null / string \| null | 해지 일시·사유 (해지일 때만. 사유는 선택이라 비어 있을 수 있음) |

**Transaction**

| 필드 | 타입 | 설명 |
|------|------|------|

| originalId | string \| null | 취소일 때 원 승인 거래 |

| 필드 | 타입 | 설명 |
|------|------|------|

| type | `credit` \| `debit` | 신청한 카드 종류 |
| productId | string | 상품 (목업은 체크 1종, 신용 1종) |

## 5. 공통 규칙

- **로그인 필요**: 카드 화면은 모두 로그인 상태에서만 열린다. 비로그인이면 로그인 화면으로 보내고, 로그인 후 원래 화면으로 돌아온다. 간편비밀번호를 설정하지 않았으면 설정 화면(S-07)으로 보낸다 ([공통 3장](../common/공통.md#3-인증접근-제어-api-규약)).
- **마스킹**: 카드 번호와 계좌 번호는 끝 4자리만 보여준다. 전체 번호는 어떤 화면에도 표시하지 않는다.
- **표기 형식**: 금액 `1,234,000원`, 날짜 `2026.11.04`, 일시 `2026.11.04 09:43` ([공통 2장](../common/공통.md#2-화면-공통))
- **화면 폭**: 모바일 420px 고정, 하단 탭(홈·계좌·카드·내 정보)
- **카드 상태별 이용 가능 기능**

| 기능 | 정상 | 일시정지 | 분실 | 해지 |
|------|:----:|:--------:|:----:|:----:|
| 목록·상세 조회 | O | O | O | O (숨김 목록에서) |
| 이용내역 조회 | O | O | O | O |
| 청구·결제 예정 확인 | O | O | O | - (청구 없음) |
| 일시정지 | O | - | - | - |
| 정지 해제 | - | O | - | - |
| 분실 신고 | O | O | - | - |
| 한도 조회 (한도 화면) | O | O | O | - |
| 해지 | O (조건 충족 시) | O (조건 충족 시) | O (조건 충족 시) | - |

해지 조건은 [07-termination.md](07-termination.md)를 따른다.

- **화면 공통 상태**: 로딩(스켈레톤 또는 문구), 빈 목록 안내, 불러오기 실패(다시 시도 버튼)를 모든 조회 화면에 둔다.
- **다른 담당과의 연결**

| 대상 | 필요한 것 |
|------|-----------|
| 일반 계좌 (김연준) | 결제 계좌 표시용 계좌 정보, 청구 시 잔액 부족 안내용 잔액, 카드 신청 시 선택할 본인 명의 저축예금 목록 (`GET /api/accounts?purpose=card_payment`) |
| 인증·회원 (김연준) | 로그인한 사용자(`current_user`), 신용카드 신청 자격(만 19세) 확인용 `get_age(user)`, 신청서 미리 채우기용 `GET /api/me`, 일시정지·정지 해제·분실 신고·카드 신청·해지 직전의 **간편비밀번호 확인**(S-08, `pin_verified(request)`) |
| 카드가 제공 (→ 계좌) | `count_active_cards(account_id)`: 계좌 해지 때 활성 카드가 있는지 확인 |

자세한 계약은 [00-api-common.md](00-api-common.md) 7절, 파트 사이 인터페이스 전체는 [공통 8장](../common/공통.md#8-파트-사이-인터페이스)이다.

## 6. 확정 사항

1. 신용카드 결제일은 1~28일 중 고르며, 기본값은 25일이다. 신청할 때 고객이 정한다.
2. 청구 이용기간은 전월 1일~전월 말일이다.
3. 일시 한도 상향은 만들지 않는다. 한도는 조회만 한다.
4. 분실 신고는 되돌릴 수 없고, 재발급은 안내 문구만 보여준다.
5. 일시정지·정지 해제·분실 신고·카드 신청·해지의 본인 확인은 **간편비밀번호 6자리** 재확인(S-08)이다. 로그인에 쓰는 6자리와 같은 값이고, 5분 안에 한 번 확인했으면 다시 묻지 않는다. 틀린 횟수는 사용자 단위로 세며 5회 틀리면 잠기고, 재설정으로만 풀린다 ([공통 4장](../common/공통.md#4-본인-재확인-2차-인증-간편비밀번호)). 계좌 암호(4자리)는 쓰지 않는다. 로그인 비밀번호는 묻지 않는다.
6. 신용카드 신청 한도는 연소득 구간별 고정표(100만~1,000만 원)로 정하고, 연소득 1,000만 원 미만은 거절한다.
7. 카드는 종류별(신용·체크) 최대 3장까지 보유할 수 있다 (해지·분실 카드 제외).
8. 신청이 끝나면 카드는 바로 "정상" 상태가 된다. 수령·사용 등록 단계는 없다.
9. 신용카드는 미결제 금액이 0원일 때만 해지할 수 있다. 정상·일시정지·분실 카드 모두 해지할 수 있다.
10. 같은 정책을 홈 자연어 입력창에도 적용한다. 채팅에서는 간편비밀번호를 받지 않고, 정지·해제·분실 신고는 확인 질문 뒤 S-08을 거쳐 실행하며, 카드 신청·해지는 화면 링크만 준다 ([08-natural-language.md](08-natural-language.md)).

## 7. 완료 기준

- 7개 기능의 화면과 API가 [00-api-common.md](00-api-common.md) 10절 기준 데이터로 동작한다.
- 정지·해제·분실 신고·신청·해지는 S-08 확인 뒤에만 실행되고, 확인하지 않았거나 5분이 지나면 `403 PIN_VERIFICATION_REQUIRED`다. 카드 상태는 바뀌지 않는다.
- 타인의 카드·계좌를 어떤 경로로 지정해도 존재하지 않는 것과 같은 404다.
- 홈 입력창에서 카드 조회(목록·이용내역·청구·한도), 정지·해제·분실 신고(확인 질문 + S-08)가 동작하고, 신청·해지는 화면 링크로 안내한다.
- 9절의 기록용 시나리오를 모두 확인하고 결과·캡처를 기록한다.
