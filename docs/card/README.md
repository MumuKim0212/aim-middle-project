# 카드 기능 기획서 (개요)

담당: 김경민 · 대상: AIM Bank 모바일 웹 · 상태: 확정

## 1. 목적과 범위

로그인한 고객이 자신의 카드를 조회하고, 이용·청구 내역을 확인하며, 분실·정지·해지 같은 긴급·변경 업무를 모바일 웹에서 처리한다.

**범위 안**
- 카드 7개 기능: 목록·상세, 이용내역, 청구·결제 예정, 분실·정지·재개, 한도 조회, 신규 발급·신청, 해지

**범위 밖 (이번에 만들지 않음)**
- 재발급 처리, 카드 수령 후 사용 등록(활성화), 신청 이력 목록
- 실제 결제 승인 처리와 결제 실행 (이용내역과 청구액은 목업 데이터로 표시)
- 한도 변경(일시 상향, 하향, 영구 변경), 현금서비스, 해외 이용 설정

## 2. 기능 목록

| # | 기능 | 한 줄 설명 | 상세 문서 | 제안 경로 |
|---|------|-----------|-----------|-----------|
| 1 | 내 카드 목록·상세 | 보유 카드, 종류(신용/체크), 결제 계좌, 한도 확인 | [01-card-list-detail.md](01-card-list-detail.md) | `/card`, `/card/:cardId` |
| 2 | 이용내역 조회 | 기간·가맹점별 조회, 승인/취소 구분 | [02-transactions.md](02-transactions.md) | `/card/transactions` |
| 3 | 청구·결제 예정 금액 | 이번 달 결제 예정액, 결제일, 결제 계좌 | [03-billing.md](03-billing.md) | `/card/billing` |
| 4 | 카드 분실·정지·재개 | 분실 신고, 일시 정지와 해제 | [04-lost-suspend.md](04-lost-suspend.md) | `/card/security` (카드 선택), `/card/:cardId/security` |
| 5 | 한도 조회 | 신용 한도·이용 금액·잔여 한도, 체크카드 1회·1일 한도 확인 | [05-limit.md](05-limit.md) | `/card/limit` (카드 선택), `/card/:cardId/limit` |
| 6 | 카드 신규 발급·신청 | 체크·신용카드 신청, 심사, 발급 결과 확인 | [06-issuance.md](06-issuance.md) | `/card/apply` |
| 7 | 카드 해지 | 미결제 금액 확인 후 카드 해지 | [07-termination.md](07-termination.md) | `/card/:cardId/terminate` |

햄버거 메뉴의 카드 항목 5개(1~5번)가 각 경로로 연결된다. 카드를 하나 골라야 하는 4·5번은 메뉴에서 들어올 때 먼저 `/card/security`, `/card/limit`의 카드 선택 목록을 보여주고, 카드 상세에서 들어올 때는 선택 없이 그 카드의 화면으로 바로 간다. 2번은 화면 안의 카드 필터로 고르고, 3번은 전체 신용카드가 대상이다. 6번은 내 카드 목록의 **카드 신청** 버튼, 7번은 카드 상세의 **카드 해지** 링크에서 들어가며 메뉴에는 넣지 않는다. 경로가 겹쳐 보이는 `/card/:cardId`와 `/card/transactions`, `/card/billing`, `/card/apply`, `/card/security`, `/card/limit`은 **고정 경로가 우선**한다 (카드 ID가 이 단어와 같을 수 없다).

**개발 문서 읽는 순서**: 먼저 [00-api-common.md](00-api-common.md)(API 공통 규칙, 오류 코드, 계좌 암호 검증, 상태 전이, 금액 계산 기준, 목업 기준 데이터)를 읽고, 만들 기능의 상세 문서(01~07)를 본다. 각 상세 문서에는 API 명세, 입력 검증, 예외·오류 처리, 프론트 구현 메모, 테스트 시나리오가 들어 있다. DB 설계·서버 구현 규칙·프론트 구조와 목업 제어 같은 개발 명세는 기획서와 분리해 [백엔드 개발 명세](../dev/card/backend-spec.md), [프론트 개발 명세](../dev/card/frontend-spec.md)에 둔다.

## 3. 화면 흐름

```
메뉴 > 카드
 ├─ 내 카드 목록·상세 ──┬─ 이용내역 (해당 카드로 필터)
 │   │                  ├─ 분실·정지·재개
 │   │                  ├─ 한도 조회
 │   │                  └─ 카드 해지 (상세에서)
 │   └─ 카드 신청 (목록의 버튼)
 ├─ 이용내역 조회 (전체 카드)
 ├─ 청구·결제 예정 금액 (전체 신용카드)
 ├─ 카드 분실·정지·재개 (카드 선택 후)
 └─ 한도 조회 (카드 선택 후)
```

## 4. 공통 데이터 모델

프론트 먼저 구현하므로 아래 형태의 목업 데이터를 `frontend/src/features/card/mock/` 에 둔다. 백엔드가 생기면 같은 형태의 API 응답으로 교체한다.

**Card**

| 필드 | 타입 | 설명 |
|------|------|------|
| id | string | 카드 식별자 |
| name | string | 카드 이름 (예: AIM 체크카드) |
| type | `credit` \| `debit` | 신용 / 체크 |
| numberMasked | string | 표시용 번호. 끝 4자리만 노출 (`****-****-****-1234`) |
| expiry | string | 유효기간 `MM/YY` |
| status | `active` \| `suspended` \| `lost` \| `terminated` | 정상 / 일시정지 / 분실 / 해지 |
| issuedAt | string | 발급일 `YYYY-MM-DD` |
| paymentAccount | { bankName, accountMasked } | 결제 계좌 (계좌 번호는 끝 4자리만 노출) |
| paymentDay | number \| null | 결제일 (신용만, 1~28, 기본 25. 신청 시 고객이 정함) |
| creditLimit | number \| null | 신용 한도 (신용만) |
| debitLimit | { perTx, perDay } \| null | 1회·1일 한도 (체크만) |
| suspendedAt | string \| null | 일시정지 일시 (정지 중일 때만) |
| lostAt / lostReason | string \| null / `lost` \| `stolen` \| null | 분실 신고 일시·사유 (분실 신고한 카드만. 이후 해지해도 유지) |
| terminatedAt / terminatedReason | string \| null / string \| null | 해지 일시·사유 (해지일 때만. 사유는 선택이라 비어 있을 수 있음) |

**Transaction**

| 필드 | 타입 | 설명 |
|------|------|------|
| id | string | 거래 식별자 |
| cardId | string | 카드 |
| occurredAt | string | 승인·취소 일시 |
| merchant | string | 가맹점명 |
| amount | number | 금액 (항상 양수, 부호는 `kind`로 표현) |
| kind | `approval` \| `cancel` | 승인 / 취소 |
| originalId | string \| null | 취소일 때 원 승인 거래 |
| installmentMonths | number | 할부 개월. 0이면 일시불 (신용만) |

**CardApplication** (신규 신청)

| 필드 | 타입 | 설명 |
|------|------|------|
| id | string | 신청 식별자 |
| type | `credit` \| `debit` | 신청한 카드 종류 |
| productId | string | 상품 (목업은 체크 1종, 신용 1종) |
| paymentAccountId | string | 결제 계좌 |
| paymentDay | number \| null | 결제일 (신용만, 기본 25) |
| incomeRange | string \| null | 연소득 구간 (신용만) |
| recipient / phone | string | 수령인, 연락처 |
| address | { line1, line2 } | 배송 주소 (`line2`는 비어 있을 수 있음) |
| agreements | { cardTerms, privacy, creditInquiry } | 약관 동의 여부 (`creditInquiry`는 신용카드만) |
| status | `approved` \| `rejected` | 심사 결과 (목업은 즉시 결정) |
| rejectReason | string \| null | 거절 사유 (거절일 때만) |
| grantedLimit | number \| null | 부여된 신용 한도 (신용 승인일 때만) |

카드 비밀번호는 신청 화면에서 형식·단순도만 확인하고 모델에 저장하지 않는다.

## 5. 공통 규칙

- **로그인 필요**: 카드 화면은 모두 로그인 상태에서만 열린다. 비로그인이면 로그인 화면으로 보낸다.
- **마스킹**: 카드 번호와 계좌 번호는 끝 4자리만 보여준다. 전체 번호는 어떤 화면에도 표시하지 않는다.
- **표기 형식**: 금액 `1,234,000원`, 날짜 `2026.11.04`, 일시 `2026.11.04 09:43`
- **카드 상태별 이용 가능 기능**

| 기능 | 정상 | 일시정지 | 분실 | 해지 |
|------|:----:|:--------:|:----:|:----:|
| 목록·상세 조회 | O | O | O | O (숨김 목록에서) |
| 이용내역 조회 | O | O | O | O |
| 청구·결제 예정 확인 | O | O | O | - (청구 없음) |
| 일시정지 | O | - | - | - |
| 정지 해제 | - | O | - | - |
| 분실 신고 | O | O | - | - |
| 한도 조회 (한도 화면) | O | O | O | - |
| 해지 | O (조건 충족 시) | O (조건 충족 시) | O (조건 충족 시) | - |

해지 조건은 [07-termination.md](07-termination.md)를 따른다.

- **화면 공통 상태**: 로딩(스켈레톤 또는 문구), 빈 목록 안내, 불러오기 실패(다시 시도 버튼)를 모든 조회 화면에 둔다.
- **다른 담당과의 연결**

| 대상 | 필요한 것 |
|------|-----------|
| 일반 계좌 (김연준) | 결제 계좌 표시용 계좌 정보, 청구 시 잔액 부족 안내용 잔액, 카드 신청 시 선택할 본인 명의 계좌 목록, 일시정지·정지 해제·분실 신고·카드 신청·해지 시 확인할 **계좌 암호** 검증 |
| 로그인·회원 | 로그인 여부 판단, 신용카드 신청 자격(만 19세) 확인용 생년월일 |

## 6. 확정 사항

1. 신용카드 결제일은 1~28일 중 고르며, 기본값은 25일이다. 신청할 때 고객이 정한다.
2. 청구 이용기간은 전월 1일~전월 말일이다.
3. 일시 한도 상향은 만들지 않는다. 한도는 조회만 한다.
4. 분실 신고는 되돌릴 수 없고, 재발급은 안내 문구만 보여준다.
5. 일시정지·정지 해제·분실 신고·카드 신청·해지의 본인 확인은 **계좌 암호** 입력(입력 팝업)이다. 숫자 4자리이고, 해당 카드(신청은 선택한)의 결제 계좌 암호를 쓴다. 5회 연속 틀리면 5분간 입력을 막는다. 로그인 비밀번호는 묻지 않는다.
6. 신용카드 신청 한도는 연소득 구간별 고정표(100만~1,000만 원)로 정하고, 연소득 1,000만 원 미만은 거절한다.
7. 카드는 종류별(신용·체크) 최대 3장까지 보유할 수 있다 (해지·분실 카드 제외).
8. 신청이 끝나면 카드는 바로 "정상" 상태가 된다. 수령·사용 등록 단계는 없다.
9. 신용카드는 미결제 금액이 0원일 때만 해지할 수 있다. 정상·일시정지·분실 카드 모두 해지할 수 있다.
